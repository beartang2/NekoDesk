# 네코 선물 — 산책에서 주워 온 물건을 그림으로

> 작성일: 2026-11-17 · 상태: 설계(1단계 구현 전 승인 필요)

## 목표

네코가 산책에서 주워 온 물건(반짝이는 병뚜껑, 도토리, 단추…)을 **네코와 같은 그림체로** 그려 선물함에 넣는다.
사용자는 그 물건을 네코 자리의 바닥이나 벽에 놓을 수 있고, 네코는 놓인 물건을 갖고 논다.

## 결정

### 1. 무엇이 물건이 되나

- 선물 종류 중 `trinket`(주운 것)과 `place`(가 본 곳)가 물건이 된다.
  - 장소 선물에는 그곳의 기념품을 붙인다. 예: 공원 나뭇잎, 카페 각설탕.
  - 날씨·읽을거리·기억·놀이는 지금처럼 글로 남는다.
- 그림(`drawing`)은 지금처럼 이미지 생성으로 보관함에 넣는다. 물건 그리기에는 이미지 생성 모델을 쓰지 않는다. 그림체가 안 맞는다.

### 2. 그리기: 모델은 모양만, 그리기는 엔진이

- 산책 머리(Claude)는 보고 툴 `walk_report` 의 인자 `gift_shape` 에 **도형 목록(JSON)** 을 적는다.
  - 지시는 이 인자의 스키마와 설명 안에만 둔다. 시스템 프롬프트는 늘리지 않는다.
- 모양 데이터(`v: 1`)
  - 좌표는 32×32 칸 기준이다. 가운데가 0이고, **y = 0 이 바닥**(물건이 놓이는 면)이며 위가 음수다.
  - 도형은 다섯 가지다.
    - `circle {x, y, r}`
    - `ellipse {x, y, rx, ry, rot}`
    - `rrect {x, y, w, h, rad, rot}`
    - `poly {pts: [[x, y]…]}`: 닫힌 다각형. 꼭짓점은 엔진이 둥글게 다듬는다.
    - `dot {x, y}`: 반짝이·무늬
  - 모든 도형에 색 `c` 를 붙인다. `c` 는 **팔레트 이름**이고, 쓸 수 있는 이름은 다음과 같다.
    - red, orange, yellow, green, teal, blue, purple, pink, brown
    - gray, white, black, gold, silver
- 엔진이 그림체를 일괄로 입힌다. 모델은 이걸 정하지 않는다.
  - 팔레트 이름을 실제 색으로 바꾼다. 소품(상자·그릇)과 같은 채도·밝기의 색으로 정해 둔다.
  - **외곽선은 그리지 않는다.** 네코와 소품은 선 없이 면으로 그려진다(neko-engine 의 상자·그릇과 같다).
  - 도형마다 위쪽에 같은 색의 밝은 면을 하나 얹고, 바닥엔 옅은 그림자 타원을 깐다.
  - 크기는 S 배율을 따른다. 처음 나올 때는 소품처럼 '뿅' 하고 나온다.
- 받은 모양 검사(`validateShape`, 순수 함수 + 테스트)
  - 모양은 데이터다. eval 하지 않고, 문자열을 그리지도 않는다.
  - 도형은 12개까지만 받는다. 모르는 종류는 버린다.
  - 숫자는 칸 안으로 자르고, 크기에 하한과 상한을 둔다. `poly` 꼭짓점은 3~10개다.
  - 팔레트에 없는 색은 gray 로 바꾼다.
  - 남은 도형이 없거나 전체가 너무 작으면 **기본 물건(동글동글한 조약돌)** 으로 대신한다.

### 3. 선물함

- 저장은 settings DB 키 `neko_gifts` 에 JSON 배열로 한다. DB 는 이미 암호화돼 있다. 새 테이블은 만들지 않는다.
  - `{ id, at, title, body, shape, play?, placed? }`
  - 최대 100개다. 넘으면 놓이지 않은 것 중 오래된 것부터 지운다.
- 산책 보고 메시지에는 지금처럼 선물 글을 남기고, "선물함에 넣어 뒀어" 한 줄을 붙인다.
- 목록 UI 는 설정의 네코 탭에 '선물함' 칸으로 둔다(결정됨).
  - 칸마다 그림, 이름, 날짜, '바닥에 놓기/치우기' 버튼이 있다.
  - 그림은 엔진의 같은 그리기 함수로 작은 캔버스에 그린다.

### 4. 배치: 무대에 묶이지 않게

- 자리는 px 가 아니라 **면 + 비율**로 저장한다. `placed: { surface: "floor" | "wall", u: 0~1, v?: 0~1 }`
  - `u` 는 양끝 여백(16·S)을 뺀 무대 폭에 대한 가로 비율이다. 걸을 수 있는 폭(사이드바에선 58px뿐)이 아니라 무대 폭이라 좁은 자리에서도 물건이 한가운데로 몰리지 않는다. `v` 는 벽에서의 세로 비율이다(2단계).
  - 크기는 S 단위다. 그래서 사이드바, 채팅 바 아래, 앞으로 생길 화면 모드 띠(docs/neko-screen-mode.md) 어디서든 같은 자리에 같은 크기로 보인다. 이번 배율 버그(소품이 옛 px 에 남음)가 구조적으로 생기지 않는다.
- 엔진 API: `ctrl.setDecor([{ id, surface, u, v, shape }])`
  - 엔진은 매 프레임 현재 W·S·floorY 로 자리를 계산해 고양이 뒤에 그린다.
- 놓는 개수는 정하지 않는다. 놓인 물건은 모두 그린다. 겹쳐도 그대로 두고, 정리는 사용자가 한다.
- 무대 위 물건은 **잡고 끌면 옮겨지고, 우클릭하면 치워진다**(선물함으로 돌아감).
  - 엔진: `hitDecor(x, y)` → 물건 id. 고양이·문 물건보다 뒤에 본다.
  - 끄는 동안은 무대 px 를 따라가고, 놓을 때 면 + 비율로 바꿔 저장한다.

### 5. 놀기(3단계)

- Claude 가 모양과 같이 `gift_play` 를 enum 에서 하나 고른다. 기존 활동 코드를 다시 쓴다.
  - `roll`: 털실 공 물리
  - `bat`: 앞발로 톡
  - `sniff`: 냄새 맡고 갸웃
  - `sit_on`: 위에 앉기. 납작한 것만 된다.
  - `carry`: 물고 옮기기
- 감독이 쉬는 시간에 가끔 '선물 갖고 놀기' 활동을 고른다. 놓인 물건이 있을 때만이다.

### 6. 입에 물기: 아무 물건이나 무는 엔진 기능

선물 전용이 아니다. 화면 모드(docs/neko-screen-mode.md)에서도 쓴다. Finder 파일을 네코 입에 끌어다 놓으면 아이콘을 물고 있다가, 입에서 끌어내면 파일이 건너간다.

- 물 수 있는 것(`CarryItem`)
  - `{ id, kind: "shape", shape }`: 위 2번의 벡터 모양. 같은 그림체로 그린다.
  - `{ id, kind: "image", image, w?, h? }`: `image` 는 이미 로드된 `ImageBitmap | HTMLImageElement` 다(macOS 파일 아이콘 PNG 등).
    - 엔진은 주소를 받아 직접 불러오지 않는다. 불러오기와 권한은 호스트 몫이다.
    - 이미지는 그림체를 입히지 않고 그대로 그린다. 진짜 파일이라는 걸 보여 주는 게 목적이다.
- API(무대 독립)
  - `ctrl.carry(item | item[])`: 입에 더한다. 이미 물고 있으면 묶음이 된다.
  - `ctrl.drop(id?)`: 입에서 뺀다. id 가 없으면 전부 뺀다. 뺀 항목을 돌려준다.
    - `{ place: { surface, u } }` 를 주면 그 자리에 장식으로 내려놓는다(선물).
  - `ctrl.carried()`: 지금 물고 있는 목록.
  - `ctrl.hitCarry(x, y)`: 그 점이 문 물건 위면 `"bundle"`, 아니면 `null`.
    - 좌표는 `hit(x, y)` 와 같은 무대 px 다(호스트가 clientX − 캔버스 rect.left 로 바꿔 넘긴다).
    - 고양이 몸 판정(`hit`)보다 먼저 본다. 그래야 입에서 끌어내기가 쓰다듬기·목덜미 잡기로 새지 않는다.
  - `ctrl.carryRect()`: 묶음이 그려진 사각형(무대 px)이다. 끌기 미리보기나 DOM 덮개 위치에 쓴다.
  - 이벤트 `carry`(문 목록이 바뀜)와 `carryPress`(문 물건 위에서 누름 — 호스트가 끌어내기를 시작한다). 목덜미 잡기의 `drop` 과 이름이 겹치지 않게 했다.
- 저장은 엔진이 하지 않는다. 입에 문 상태는 앱 세션 동안만이고, 자리·크기와 무관하다.
  - 그리는 자리는 매 프레임 머리의 입 기준점(머리 로컬 좌표 → `H2W`)에서 구한다. 그래서 사이드바, 아래 띠, 화면 띠 어디서든, 크기가 바뀌어도 그대로 따라간다(이번 배율 버그와 같은 문제가 안 생긴다).
- 그리기
  - 묶음은 최대 3개를 부채처럼 겹쳐 그린다. 크기는 S 단위로 상한을 둔다(머리보다 작게).
  - 고개 기울기·흔들림을 따라 살짝 늦게 흔들린다.
  - 숫자는 쓰지 않는다(결정됨). 1장이면 하나, 2장 이상이면 2~3장이 겹쳐 보여서 하나인지 여럿인지만 드러난다. '고양이 주변 글자 없음' 규칙을 그대로 지킨다.
- 다른 동작과의 관계
  - 입을 쓰는 활동(간식·밥·빈 그릇·세수) 중엔 문 물건을 머리 앞 바닥에 잠깐 내려 두고, 끝나면 다시 문다. 엔진 안에서만 처리해 감독은 바꾸지 않는다.
  - 누워 자면 묶음을 머리 앞 바닥에 내려 둔다. 논리상으로는 계속 물고 있는 상태라 `hitCarry` 가 그대로 된다.
  - 목덜미를 잡혀도 놓치지 않는다.
- 선물의 `carry`(물고 옮기기, 3단계)도 이 API 를 그대로 쓴다.

## 단계

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| 1-물기 | 엔진의 입에 물기 API(6번): 벡터·이미지, 묶음·배지, `hitCarry`·`carryRect` | QA 하네스에서 이미지·모양을 물리고 자리·크기를 바꿔도 입을 따라간다. `hitCarry` 가 문 물건 위에서만 참이다. 화면 모드 세션이 이것만으로 붙일 수 있다 |
| 1 | 모양 데이터·검사, 선물함 저장·목록, 바닥에 정지 장식으로 놓기 | 산책 `trinket` 이 그림 물건으로 선물함에 들어간다. 놓기를 누르면 무대 바닥에 보이고, 자리 옮김·높이 끌기에도 같은 자리·크기를 지킨다. `validateShape` 테스트와 엔진 QA(배치 정렬)가 통과한다 |
| 2 | 선물함에서 무대로 끌어 놓기, 무대 위에서 잡고 끌어 옮기기·우클릭 치우기, 벽에 걸기 | 끌어서 바닥·벽 아무 데나 놓고 비율로 저장된다. 우클릭하면 선물함으로 돌아간다 |
| 3 | `gift_play` 와 감독 연결 | 놓인 물건으로 네코가 가끔 논다 |

## 정해 주실 것

결정됨: 선물함은 설정의 네코 탭, 장소 선물도 기념품 물건, 선물함 100개, 무대 개수는 정하지 않음(끌어 옮기기·우클릭 치우기),
문 물건은 숫자 없이 1~3장 겹침, 순서는 '1-물기' 먼저.
