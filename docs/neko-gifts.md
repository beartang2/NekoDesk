# 네코 선물 — 산책에서 주워 온 물건을 그림으로

> 작성일: 2026-11-17 · 상태: 설계(1단계 구현 전 승인 필요)

## 목표

네코가 산책에서 주워 온 물건(반짝이는 병뚜껑, 도토리, 단추…)을 **네코와 같은 그림체로** 그려 선물함에 넣는다.
사용자는 그 물건을 네코 자리의 바닥이나 벽에 놓을 수 있고, 네코는 놓인 물건을 갖고 논다.

## 결정

### 1. 무엇이 물건이 되나

- 선물 종류 중 `trinket`(주운 것)만 물건이 된다. 장소·날씨·읽을거리·기억·놀이는 지금처럼 글로 남는다.
- 그림(`drawing`)은 지금처럼 이미지 생성으로 보관함에 넣는다. 물건 그리기에는 이미지 생성 모델을 쓰지 않는다. 그림체가 안 맞는다.

### 2. 그리기: 모델은 모양만, 그리기는 엔진이

- 산책 머리(Claude)는 보고 툴 `walk_report` 의 인자 `gift_shape` 에 **도형 목록(JSON)** 을 적는다.
  - 지시는 이 인자의 스키마와 설명 안에만 둔다. 시스템 프롬프트는 늘리지 않는다.
- 모양 데이터(`v: 1`)
  - 좌표는 32×32 칸 기준이다. 가운데가 0이고, **y = 0 이 바닥**(물건이 놓이는 면)이며 위가 음수다.
  - 도형은 다섯 가지다.
    - `circle {x, y, r}`
    - `ellipse {x, y, rx, ry, rot}`
    - `rrect {x, y, w, h, rad, rot}`
    - `poly {pts: [[x, y]…]}`: 닫힌 다각형. 꼭짓점은 엔진이 둥글게 다듬는다.
    - `dot {x, y}`: 반짝이·무늬
  - 모든 도형에 색 `c` 를 붙인다. `c` 는 **팔레트 이름**이고, 쓸 수 있는 이름은 다음과 같다.
    - red, orange, yellow, green, teal, blue, purple, pink, brown
    - gray, white, black, gold, silver
- 엔진이 그림체를 일괄로 입힌다. 모델은 이걸 정하지 않는다.
  - 팔레트 이름을 실제 색으로 바꾼다. 소품(상자·그릇)과 같은 채도·밝기의 색으로 정해 둔다.
  - **외곽선은 그리지 않는다.** 네코와 소품은 선 없이 면으로 그려진다(neko-engine 의 상자·그릇과 같다).
  - 도형마다 위쪽에 같은 색의 밝은 면을 하나 얹고, 바닥엔 옅은 그림자 타원을 깐다.
  - 크기는 S 배율을 따른다. 처음 나올 때는 소품처럼 '뿅' 하고 나온다.
- 받은 모양 검사(`validateShape`, 순수 함수 + 테스트)
  - 모양은 데이터다. eval 하지 않고, 문자열을 그리지도 않는다.
  - 도형은 12개까지만 받는다. 모르는 종류는 버린다.
  - 숫자는 칸 안으로 자르고, 크기에 하한과 상한을 둔다. `poly` 꼭짓점은 3~10개다.
  - 팔레트에 없는 색은 gray 로 바꾼다.
  - 남은 도형이 없거나 전체가 너무 작으면 **기본 물건(동글동글한 조약돌)** 으로 대신한다.

### 3. 선물함

- 저장은 settings DB 키 `neko_gifts` 에 JSON 배열로 한다. DB 는 이미 암호화돼 있다. 새 테이블은 만들지 않는다.
  - `{ id, at, title, body, shape, play?, placed? }`
  - 최대 40개다. 넘으면 놓이지 않은 것 중 오래된 것부터 지운다.
- 산책 보고 메시지에는 지금처럼 선물 글을 남기고, "선물함에 넣어 뒀어" 한 줄을 붙인다.
- 목록 UI(1단계)는 설정의 네코 탭에 '선물함' 칸으로 둔다.
  - 칸마다 그림, 이름, 날짜, '바닥에 놓기/치우기' 버튼이 있다.
  - 그림은 엔진의 같은 그리기 함수로 작은 캔버스에 그린다.

### 4. 배치: 무대에 묶이지 않게

- 자리는 px 가 아니라 **면 + 비율**로 저장한다. `placed: { surface: "floor" | "wall", u: 0~1, v?: 0~1 }`
  - `u` 는 걸을 수 있는 폭 안의 가로 비율이다. `v` 는 벽에서의 세로 비율이다(2단계).
  - 크기는 S 단위다. 그래서 사이드바, 채팅 바 아래, 앞으로 생길 화면 모드 띠(docs/neko-screen-mode.md) 어디서든 같은 자리에 같은 크기로 보인다. 이번 배율 버그(소품이 옛 px 에 남음)가 구조적으로 생기지 않는다.
- 엔진 API: `ctrl.setDecor([{ id, surface, u, v, shape }])`
  - 엔진은 매 프레임 현재 W·S·floorY 로 자리를 계산해 고양이 뒤에 그린다.
- 한 무대에 바닥 3개, 벽 2개까지 놓는다. 좁은 사이드바가 어지러워지지 않게 한다.

### 5. 놀기(3단계)

- Claude 가 모양과 같이 `gift_play` 를 enum 에서 하나 고른다. 기존 활동 코드를 다시 쓴다.
  - `roll`: 털실 공 물리
  - `bat`: 앞발로 톡
  - `sniff`: 냄새 맡고 갸웃
  - `sit_on`: 위에 앉기. 납작한 것만 된다.
  - `carry`: 물고 옮기기
- 감독이 쉬는 시간에 가끔 '선물 갖고 놀기' 활동을 고른다. 놓인 물건이 있을 때만이다.

## 단계

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| 1 | 모양 데이터·검사, 선물함 저장·목록, 바닥에 정지 장식으로 놓기 | 산책 `trinket` 이 그림 물건으로 선물함에 들어간다. 놓기를 누르면 무대 바닥에 보이고, 자리 옮김·높이 끌기에도 같은 자리·크기를 지킨다. `validateShape` 테스트와 엔진 QA(배치 정렬)가 통과한다 |
| 2 | 선물함에서 무대로 끌어 놓기, 벽에 걸기 | 끌어서 바닥·벽 아무 데나 놓고 비율로 저장된다 |
| 3 | `gift_play` 와 감독 연결 | 놓인 물건으로 네코가 가끔 논다 |

## 정해 주실 것

1. **선물함 자리**: 설정의 네코 탭(1단계 추천, 구현이 가장 작다)으로 할지, 네코 무대 구석의 작은 선물 버튼 팝업으로 할지.
2. **물건이 되는 선물**: `trinket` 만으로 할지, 장소 선물에도 기념품(공원 나뭇잎 등)을 붙일지.
3. **개수 상한**: 선물함 40개, 무대에 바닥 3개·벽 2개. 이대로 갈지.
