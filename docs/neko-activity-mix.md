# 네코 활동 겹치기와 욕구로 고르기

> 작성일: 2026-11-18 · 상태: 설계(구현 전 사용자 확인 필요)
> 바탕: 감독 3e6e4d9·849fd83·877fb00(미용사), 엔진 62b32a9·0966b7a(헤드폰). 감독 설계는 [neko-p2-director.md](neko-p2-director.md).

## 목표

1. **겹치기(1단계).** 함께 할 수 있는 활동은 같이 한다. 예: 음악 들으며 타이핑하기, 음악 들으며 신문 읽기.
   - 조합을 손으로 적지 않는다. 활동마다 "몸의 어디를 쓰는지"를 선언하고, 함수 하나가 두 선언을 보고 같이 할 수 있는지 정한다.
2. **고르기(2단계).** 혼자 놀 때 무엇을 할지 숨은 욕구 점수로 고른다(심즈 방식).
   - 새 활동은 선언에 "무엇을 채워 주는지"만 적으면 된다. 감독 코드는 안 고친다.

두 단계는 따로 구현하고 따로 확인한다. 2단계는 1단계 위에 얹는다.

## 지금 모양

- 엔진은 활동을 **하나만** 한다(`cat.act`). `act(key)` 로 바꾸면 소품이 쏙 들어가고 새 소품이 뿅 나온다.
- 활동 하나 = `defineActivity(key, spec)` 하나. 지금 22개다:
  draw · music · butterfly · snack · stretch · typing · reading · stamp · groom · knead · yarn · giftplay · box · window · think · wait · meal · hungry · dig · calendar · erase · climb.
- `spec.pose(A, ramp)` 가 매 프레임 자세 객체를 돌려준다. 엔진은 그 키를 읽어 몸·다리·머리·귀·꼬리를 움직인다(§1.3 표).
- 감독(`derive.ts`)이 층 순서대로 활동 하나를 고른다.
  - 혼자 놀기는 `pickSolo(직전, 선물 있음)` 로 `SOLO` 12개 중 하나를 고르게 뽑는다. 부르는 곳은 `useNekoDirector.ts` 한 곳이다.
  - 다른 앱 따라 하기(`ambient.ts`)는 음악이 나오면 `outside.activity = "music"` 으로 둔다. 그래서 다른 앱에서 타이핑하는 동안에는 음악 듣기가 안 보인다(타이핑 층이 이긴다).

## 1부. 겹치기 (1단계)

### 1.1 주 활동과 곁들임

- **주 활동**은 하나다. 지금의 `act(key)` 그대로다. 몸 자세·소품 자리·돌아다니기를 정한다.
- **곁들임**은 주 활동 위에 얹는 활동이다. 0개 또는 1개다.
- 처음 곁들임이 되는 활동은 **음악 듣기 하나**다. 다른 활동은 모두 주 활동만 한다.

### 1.2 부위

부위는 일곱 개로 정한다. 매니저 안 그대로다.

| 부위 | 키 | 무엇 |
|---|---|---|
| 몸 | `body` | 서기·앉기·식빵, 몸 기울기·높이·눌림 |
| 이동 | `move` | 걸어 다니기·뛰기·벽 타기(돌아다니는 활동) |
| 앞발 | `paws` | 앞발 자리(붓 쥐기, 키 누르기, 세수…) |
| 머리 | `head` | 머리 자리·갸웃, 시선, 표정·눈꺼풀 |
| 귀 | `ears` | 귀 각도 |
| 입 | `mouth` | 먹기·핥기·물기 |
| 꼬리 | `tail` | 꼬리 모양 |

- 표정과 눈꺼풀은 머리에 넣는다. 따로 떼어도 지금은 얻는 게 없다(곁들임이 표정을 바꾸지 않는다, §1.5).
- 입과 이동은 자세 키가 없다. 차지했는지만 본다.

### 1.3 자세 키 → 부위

엔진이 읽는 `pose()` 키를 모두 부위에 나눈다. 조합기는 이 표로 "누구의 값을 쓸지"를 정한다.

| 부위 | pose 키 |
|---|---|
| 몸 | `sit` `loaf` `tilt` `dy` `sq` `pos` `bend` `bendW` |
| 앞발 | `feet` `feetW` `reach` `pawFront` `pawBeans` |
| 머리 | `head` `tt` `look` `expr` `lid` |
| 귀 | `ear` |
| 꼬리 | `tail` |

이 표에 없는 키가 `pose()` 에 생기면 QA 가 실패한다(§1.11).

### 1.4 선언 형식

선언은 **엔진 밖의 순수 모듈** `src/neko/engine/activity-mix.js` 에 둔다(`.d.ts` 와 테스트를 같이 둔다).

- 감독도 같은 선언과 같은 함수를 써야 한다.
- 감독이 엔진에 물어보면 안 된다. 화면 모드에선 엔진이 다른 창에 있어서, 대리 컨트롤러는 값을 바로 돌려줄 수 없다.
- 그래서 선언은 데이터로 따로 두고, 엔진과 감독이 둘 다 import 한다.

```js
// src/neko/engine/activity-mix.js
export const PARTS = ["body", "move", "paws", "head", "ears", "mouth", "tail"];

export const MIX = {
  typing: { hold: ["body", "paws", "head", "ears", "tail"], stance: "sit", slots: ["floor"] },
  music: {
    ride: ["body", "head", "ears"],   // 곁들일 때 더하는 부위
    stance: "sit",
    role: "both",                     // 주 활동도, 곁들임도
    needs: ["sit", "loaf"],           // 곁들일 때 주 활동이 앉거나 식빵이어야
    slots: ["head"],
    with: "음악 들으며",
    notWith: ["groom", "box"],
  },
  // … 22개 모두(§1.9)
};
```

| 필드 | 뜻 | 없으면 |
|---|---|---|
| `hold` | 차지하는 부위. 그 부위 값은 이 활동이 정한다 | `[]` |
| `ride` | 얹는 부위. 다른 활동 값 위에 조금 더한다(§1.6) | `[]` |
| `stance` | 이 활동의 몸 자세: `sit` · `loaf` · `stand` · `move` | `stand` |
| `needs` | 곁들임으로 얹힐 때, 주 활동의 `stance` 가 이 중 하나여야 한다 | 아무 자세 |
| `slots` | 소품 자리: `floor`(앞 바닥) · `wall`(벽·창) · `air`(공중) · `head`(머리에 씀) · `decor`(놓인 선물) | `[]` |
| `role` | `main`(주 활동만) · `both`(곁들임도) | `main` |
| `with` | 곁들일 때 상태 글자 앞말 | — |
| `notWith` | 부위로는 되지만 보기 어색해서 같이 안 하는 활동 | `[]` |
| `fills` · `solo` | 2단계(§2.3) | — |

- **선언이 없는 활동은 "전부 차지함"이다.** 지금처럼 혼자 한다. 시안 하네스의 `wave` 처럼 밖에서 더한 활동도 그렇다.
- 엔진 `defineActivity` 의 spec 에는 `mix` 를 넣을 수 있다. 엔진은 `spec.mix ?? MIX[key] ?? 전부 차지함` 순서로 쓴다.
- 얹는 부위가 있는 활동은 spec 에 `overlay(A, ramp)` 를 더한다. 얹을 때 더할 값(차이)을 돌려준다. 이 함수는 엔진 안의 코드다(박자 같은 엔진 상태를 쓴다).

```js
defineActivity("music", {
  // … 지금 그대로(start·step·pose) …
  overlay(A, ramp) { // 곁들일 때: 고개 까딱·몸 통통·귀 살짝 눕히기만
    const beat = Math.max(0, Math.sin(A.t * 1.6 * TAU));
    return { tt: 0.09 * beat * ramp, sq: -0.025 * beat * ramp, ear: 0.1 * ramp };
  },
});
```

### 1.5 조합기: 같이 할 수 있나

`mixable(main, side)` → `{ ok, why }`. 순수 함수이고 엔진 상태를 안 쓴다. 아래 순서로 처음 걸리는 이유를 돌려준다.

1. 같은 활동이면 불가(`why: "같은 활동"`).
2. 곁들임의 `role` 이 `both` 가 아니면 불가(`"곁들임 아님"`).
3. 어느 한쪽의 `notWith` 에 상대가 있으면 불가(`"같이 안 함"`).
4. **둘 다 차지하는 부위**가 있으면 불가(`"부위: 앞발·머리"`).
   - 차지함 + 얹음은 된다. 얹음 + 얹음도 된다.
5. 곁들임에 `needs` 가 있고 주 활동의 `stance` 가 그 안에 없으면 불가(`"자세"`).
6. 소품 자리가 겹치면 불가(`"소품 자리: floor"`).

곁들임으로 얹힌 음악은 주 활동의 표정·눈을 바꾸지 않는다. 그래서 신문을 읽으면 눈은 줄을 따라가고, 고개만 박자에 까딱인다.

### 1.6 자세 합치기

`mergePose(mainKey, sideKey, mainPose, sidePose, sideOverlay)` → 자세 하나. 이것도 같은 순수 모듈에 둔다.

1. 부위마다 **차지한 쪽**의 pose 키를 쓴다. 아무도 차지하지 않은 부위는 주 활동 값을 쓴다(없으면 엔진 기본값).
2. 얹는 쪽의 `overlay()` 값은 새 키 `add` 에 모은다. 예: `add: { tt, sq, ear, tilt, dy }`.
3. 엔진은 각 값을 다 정한 **뒤에** `add` 를 더한다. 주 활동이 그 키를 정했든 안 정했든 같다. 고칠 곳은 다섯 군데다.
   - `tt`(머리 갸웃)·`ear`(귀)·`sq`(몸 눌림)·`tilt`(몸 기울기)·`dy`(몸 높이).

키별 규칙을 따로 두지 않는다. 이 방식이 더 단순하다. "차이를 더한다"는 규칙 하나면 된다.

예: 타이핑 + 음악
- 몸·앞발·머리·귀·꼬리는 타이핑 값을 쓴다. 두 발로 톡톡 치고, 눈은 화면을 본다.
- `add` 에는 음악 박자가 들어간다: 고개 +0.09, 몸 −0.025, 귀 +0.1.

### 1.7 소품

- 곁들임의 `kit.back` / `kit.front` 소품은 곁들임 자기 목록에 둔다. 뿅 나오고 쏙 들어가는 것도 각자 한다.
- 그리는 순서는 같은 층 안에서 **주 활동 소품 → 곁들임 소품**이다.
  - 헤드폰(`head` 자리, 앞 층)은 이젤·노트북·신문 같은 앞 소품보다 나중에 그려진다. 그래서 늘 위에 보인다.
- 소품 자리가 겹치는 조합은 §1.5 의 6번에서 이미 막힌다. 따라서 바닥 소품 두 개가 겹쳐 그려지는 일은 없다.

### 1.8 엔진 동작

| 경우 | 동작 |
|---|---|
| `side(key)` | 곁들임을 시작한다. 주 활동이 없거나 `mixable` 이 아니면 거절한다(`false` 를 돌려주고 `"side"` 이벤트는 `null`). |
| `side(null)` | 곁들임을 끝낸다(소품이 쏙 들어간다). |
| 주 활동이 바뀜 | 새 주 활동과도 되면 곁들임이 이어진다(헤드폰 그대로). 안 되면 곁들임을 끝낸다. |
| 주 활동이 끝남 | 끝나는 이유는 `act(null)`, 한 번짜리가 끝남, 잡혀서 그만둠 중 하나다. 그러면 **곁들임이 주 활동으로 올라간다(이어받기).** 소품은 다시 뜨지 않는다. `"activity"` 이벤트로 `music` 을, `"side"` 이벤트로 `null` 을 보낸다. |
| `act(k)` 이고 k 가 지금 곁들임 | 곁들임을 주 활동으로 옮긴다(이어받기와 같다). |
| 잡기 | `keepOnGrab` 을 활동마다 따로 본다. 주 활동이 잡혀서 끝나면 이어받기가 된다. 음악은 `keepOnGrab` 이라 계속된다. |
| 매 프레임 | 주 활동 `step` 다음에 곁들임 `step`. `room`·`look`·`wander` 는 주 활동 것만 쓴다. |
| 상태 글자 | `with + " " + 주 활동 label`. 예: "음악 들으며 타이핑하는 중". |
| 산책 팻말(`setAway`) | 지금처럼 `step` 이 멈춘다. 곁들임도 같이 멈춘다. |

컨트롤러에 더할 것: `side(key | null): boolean`, `get side()`, 이벤트 `"side"`.

  - 잡기와 화면 모드 크기(`?world=1&fixed=0.8`)도 본다.

### 1.12 잡기·화면 모드·대리 컨트롤러

- **잡기**: §1.8 대로다. 지금 `keepOnGrab` 이 있는 활동(음악·나비·털실·선물)은 그대로다.
- **화면 모드**: 소품은 고양이 둘레 영역에 그려지고 머리를 따라간다. 따로 고칠 것은 없다. 헤드폰 크기는 화면 모드에서도 확인했다(62b32a9).
- **대리 컨트롤러(`remoteNeko.ts`)**
  - `side()` 는 프록시가 그대로 넘긴다.
  - 고칠 것 둘:
    1. `side` 게터를 `activity` 처럼 대리에서 답한다. `"side"` 이벤트로 바로잡는다.
    2. 화면 창이 새로 열려 `ready` 가 오면, 지금 곁들임을 다시 보낸다(`setAway` 를 다시 보내는 것과 같은 자리).
  - `remoteNeko.test.ts` 의 ready 명령 기대값에 `side` 를 더한다.

### 1.13 감독 (1단계)

1단계 감독은 **실제로 음악이 나올 때만** 곁들인다. 무작위로 곁들이는 것은 2단계에서 점수로 한다.

- `ambient.ts`: 음악을 활동에서 떼어 낸다. `OutsideState` 에 `music: boolean` 을 더한다.
  - `activity` 는 앱으로만 정한다: `own ? null : appActivity(app)`.
  - 미용사가 짚은 대로, 이렇게 해야 음악이 "ambient 의 주 활동"과 "곁들임" 두 갈래로 갈라지지 않는다.
- `types.ts`: `NekoPlan.side: NekoActivity | null`(기본 `null`).
- `derive.ts`
  - 계획을 정한 뒤 마지막에 한 번 본다. `outside.music` 이고 `mixable(plan.activity, "music").ok` 면 `side = "music"`.
  - 주 활동이 없고 음악만 나오면, 지금처럼 ambient 층이 `music` 을 주 활동으로 둔다(`outside.activity ?? (outside.music ? "music" : null)`).
  - 예: 다른 앱에서 타이핑 + 음악 → typing + music. 에이전트가 신문 읽기 + 음악 → reading + music. 세수 + 음악 → 세수만.
- `scheduler.ts`
  - 계획을 적용할 때 엔진의 `side` 와 `plan.side` 가 다르면 `ctrl.side(plan.side)` 를 부른다.
  - 엔진이 곁들임을 끝내거나 이어받기를 하면 `"side"` / `"activity"` 이벤트가 온다. 그때 지금 계획으로 다시 맞춘다. 엔진이 끝낸 한 번짜리를 바로잡는 지금 방식과 같다.
  - 곁들임에는 머무름(dwell)을 두지 않는다. 음악 확인은 15초마다라서 깜빡이지 않는다.
- 혼자 놀기의 `SOLO` 에는 `music` 을 그대로 둔다. 혼자 앉아 음악만 듣는 놀이다. 곁들임과는 다른 경우라 두 갈래가 아니다.

## 2부. 욕구로 고르기 (2단계)

### 2.1 무엇이 바뀌나

- **언제** 혼자 놀지는 지금 그대로다: 놀이 ≥ 40, 쉬는 중, 45초~2분 뒤, 2~4분 머무름, 쓰다듬기 3번이면 그만.
- **무엇을** 할지만 점수로 고른다. `pickSolo` 의 고르게 뽑기를 점수에 비례한 확률로 바꾼다.
- 일할 때 활동(도구·답 쓰기·다른 앱 따라 하기)은 도구와 앱이 정한다. 점수 대상이 아니다.
- 보이는 게이지 둘(배고픔·놀이)은 숫자도 UI 도 안 바꾼다.
  - 놀이는 "언제 놀지" 문으로 그대로 쓴다.
  - 미용사는 놀이와 호기심이 같은 일을 하면 합치자고 했다. 합치지 않는다. 놀이는 **사용자가 채우는** 보이는 게이지(놀아주기·쓰다듬기)다. 호기심은 **네코가 스스로 채우는** 숨은 게이지(창밖·산책)다. 채우는 쪽이 다르다.
- 졸음은 지금 규칙 그대로다(무활동 5분 식빵, 6분 누워 자기). 기운이 잠을 정하지 않는다. 자는 동안 기운이 찰 뿐이다.

### 2.2 숨은 게이지 넷

모두 0~100이고 처음 값은 70이다.

| 게이지 | 깨어 있을 때 저절로 | 앱이 꺼져 있던 동안 | 바닥(꺼져 있던 동안) | 채우는 일 / 떨어뜨리는 일 |
|---|---|---|---|---|
| 기운 `energy` | −4/시간 | **+40/시간**(잔 것으로 본다) | — | 졸기 +20/시간, 누워 자기 +40/시간. 활동적인 놀이는 깎는다(§2.3) |
| 호기심 `curiosity` | −10/시간 | −10/시간 | 30 | 창밖·뒤지기·선물·신문(§2.3). **산책 다녀오면 100** |
| 청결 `clean` | −4/시간 | −4/시간 | 40 | 세수 +35. 간식·밥 뒤 −10, 산책 뒤 −20 |
| 애정 `affection` | −8/시간(대화·쓰다듬기가 10분 넘게 없을 때만) | −8/시간 | 30 | 메시지 보내기 +10, 쓰다듬기 +3(10분에 +15까지). 꾹꾹이도 조금 채운다(§2.3) |

- 산책을 다녀오면 기운도 −15 된다.
- 바닥은 "오래 꺼 두었다가 켜도 너무 심하게 굶주린 상태로 시작하지 않게" 둔다. 깨어 있는 동안은 0까지 내려갈 수 있다.

### 2.3 채움 표

같은 `MIX` 선언에 두 필드를 더한다.

- `fills`: 한 번(약 3분) 하면 바뀌는 양. 하는 동안 1분마다 `fills ÷ 3` 씩 반영한다. 한 번짜리(간식·기지개·벽 타기)는 끝날 때 한 번에 반영한다.
- `solo: true`: 혼자 놀기 후보. 지금 `derive.SOLO` 목록이 이 필드로 옮겨 온다. 새 활동은 `solo` 와 `fills` 만 적으면 후보가 된다.

- 곁들임도 채운다. 타이핑 + 음악이면 둘 다 반영한다.
- 매니저 안의 "애정이 낮으면 쳐다보기·커서 따라오기"는 지금 활동에 맞는 것이 없다. 처음엔 꾹꾹이만 애정 후보로 둔다. "쳐다보기" 활동을 새로 만들지는 사용자가 정한다(맨 끝 목록 6).

### 2.4 점수 식

후보 활동 k 마다:

```
모자람 u(v)   = ((100 − v) / 100)²             호기심·청결·애정
기운 균형 e   = (50 − 기운) / 50                 −1(넘침) ~ +1(바닥)
점수 U(k)     = max(0.1, 1 + 0.15·Σ fills_k[n]·u(v_n) + 0.06·fills_k[기운]·e)
확률          ∝ U(k)     (직전 활동은 뺀다, 놓인 선물이 있으면 giftplay ×2)
```

- 모자랄수록 그 욕구를 채우는 활동의 점수가 가파르게 오른다(제곱). 거의 찬 욕구는 거의 안 끈다.
- 기운은 양쪽으로 본다. 넘치면 기운을 쓰는 놀이(나비·털실·벽 타기)가 올라가고, 바닥이면 쉬는 놀이가 올라간다.
- 기본 1 덕분에 어떤 활동도 0이 되지 않는다. 가끔 엉뚱한 놀이도 나온다.

**예 1 — 기운 넘치고 심심함**(기운 80 · 호기심 40 · 청결 70 · 애정 60)

| 활동 | 점수 | 확률 |
|---|---|---|
| climb 벽 타기 | 2.62 | 12% |
| butterfly 나비 | 2.44 | 12% |
| dig 뒤지기 | 2.26 | 11% |
| window 창밖 | 2.24 | 11% |
| yarn 털실 | 1.99 | 9% |
| reading 신문 | 1.90 | 9% |
| draw 그림 | 1.72 | 8% |
| groom · box | 1.36 | 6% · 6% |
| music | 0.98 | 5% |
| knead · snack · stretch | 0.83 · 0.69 · 0.64 | 4% · 3% · 3% |

**예 2 — 지치고 꼬질하고 외로움**(기운 15 · 호기심 80 · 청결 30 · 애정 20)

| 활동 | 점수 | 확률 |
|---|---|---|
| groom 세수 | 3.70 | 24% |
| knead 꾹꾹이 | 2.19 | 14% |
| stretch · music · reading | 1.42 · 1.37 · 1.33 | 9% · 9% · 9% |
| window · box | 1.28 · 1.27 | 8% · 8% |
| dig · draw | 0.91 · 0.85 | 6% · 6% |
| snack | 0.48 | 3% |
| yarn · butterfly · climb | 0.19 · 0.10 · 0.10 | 1% · 1% · 1% |

(두 예는 dig 를 후보에 넣고, 놓인 선물은 없다고 본 값이다.)

### 2.5 곁들임 고르기

- 주 활동 k 를 고른 뒤, `role: both` 이고 `mixable(k, s)` 인 곁들임 s 마다 확률 `clamp((U(s) − 0.6) / 2, 0, 0.6)` 로 얹는다. 지금은 음악 하나뿐이다.
  - 예 1: 음악 점수 0.98 → 19%. 예 2: 1.37 → 39%.
- 실제로 음악이 나오는 중이면 점수와 상관없이 얹는다(1단계 규칙).
- 주 활동이 음악이면 곁들임은 없다.

### 2.6 저장

- 설정 키 `neko_needs` 에 `{ energy, curiosity, clean, affection, at }` 을 JSON 으로 둔다. `cat_rpg_state` 와 같은 방식이다.
- 켤 때 `at` 부터 지난 시간만큼 §2.2 의 "꺼져 있던 동안" 속도를 적용하고 바닥에서 멈춘다.
- 1분마다 갱신한다. 저절로 떨어지는 양, 지금 하는 활동(주·곁들임)의 채움, 졸기·누워 자기를 반영하고 저장한다.
- 메인 창에서만 돈다. 화면 창은 감독을 안 돌린다.

### 2.7 감독을 어떻게 바꾸나

미용사가 남긴 조건(직전 제외, 선물 가중, draw 면 `maybeDraw`, 대기·머무름 타이머 그대로)을 모두 지킨다.

- 새 순수 모듈 `src/neko/director/needs.ts`
  - `decay(state, ms, how)`: 깨어 있음 / 졸기 / 누워 자기 / 꺼져 있음.
  - `applyFill(state, key, minutes)`.
  - `score(state, decl)`.
  - `pickByNeeds(state, { last, hasGifts }, r)` → `{ main, side }`.
- 새 스토어 `useNekoNeeds`(`director/stores.ts` 옆): 불러오기·저장·1분 틱·사건 반영.
- `useNekoDirector.ts`
  - `pickSolo(lastSolo, hasGifts)` 자리를 `pickByNeeds(...)` 로 바꾼다. `box = { since, kind: main, side }`.
  - 그 뒤 줄(draw 면 `maybeDraw`, 머무름 타이머)은 그대로다.
  - 1분 틱에서 `ctrl.activity` · `ctrl.side` · 졸림 층을 읽어 채움을 반영한다.
  - 사건을 반영한다.
    - `ctrl.on("pet")` → 애정 +3.
    - 세션 `run_start`(사용자가 보냄) → 애정 +10.
    - 밥 끝(`fedAt`) → 청결 −10.
    - 산책 귀가 → 호기심 100, 청결 −20, 기운 −15. App 의 산책 끝 자리에서 한 줄 부른다.
- `derive.ts`
  - box 층의 `side = box.side`, 그 밖은 1단계 음악 규칙을 쓴다.
  - `SOLO` 는 `MIX` 의 `solo` 로 바꾼다. `ROAMING` 은 `stance === "move"` 로 바꿀 수 있다.
  - `DirectorInput` 에는 숨은 게이지를 넣지 않는다. 고르는 일은 지금처럼 `useNekoDirector` 의 타이머에서 하고, `derive` 는 순수하게 둔다.
- 개발 빌드에서만 보이는 게이지 화면
  - 설정 › 고양이 맨 아래(`import.meta.env.DEV`)에 둔다.
  - 넷의 막대와 숫자를 보여 준다. 칸마다 −30 / +30 버튼을 둔다.
  - "다음 혼자 놀기 확률" 상위 5개를 보여 준다.
  - `window.__nekoNeeds` 로도 읽고 쓸 수 있다.

### 2.8 처음엔 안 하는 것

- 호기심이 낮을 때 산책을 일찍 보내지 않는다. 산책 시각은 지금 규칙(정기 산책·추가 산책) 그대로다.
- 숨은 게이지를 말풍선·대사·시스템 프롬프트에 싣지 않는다.
- 일할 때 활동을 점수로 바꾸지 않는다.
- 기운으로 잠을 정하지 않는다.

## 사용자가 정할 것

1. **음악을 곁들이는 자리**: 10개 조합(§1.10) 중 `wait`(확인을 기다림)·`hungry`(빈 그릇 앞)에서도 헤드폰을 쓸지. 둘 다 사용자를 보는 장면이다.
2. **같이 안 함**: 세수·상자 두 개가 맞는지. 서서 하는 꾹꾹이·간식도 음악과 같이 할지(지금은 자세 조건으로 안 된다).
3. **1단계 곁들임**: 실제로 음악이 나올 때만 할지(이 문서의 안), 혼자 놀 때 무작위로도 할지.
4. **꺼져 있던 동안의 기운**: 잔 것으로 보고 오르게 할지(이 문서의 안), 그대로 둘지.
5. **숫자**: 처음 값 70, §2.2 의 속도·바닥, §2.3 의 채움 값.
6. **애정이 낮을 때**: "쳐다보기" 활동을 새로 만들지(엔진에 활동 하나 추가). 아니면 처음엔 꾹꾹이만 둘지.
7. **상자 뒤지기(dig)**: 혼자 놀기 후보에 넣을지. 호기심을 채우는 활동이라 매니저 안에 있지만, 지금은 파일 도구 활동이다.
8. **뽑는 방식**: 점수 그대로 비례(가끔 엉뚱한 놀이, 이 문서의 안)로 할지, 점수 제곱 비례(욕구를 더 뚜렷이 따름)로 할지.
