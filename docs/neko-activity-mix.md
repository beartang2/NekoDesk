# 네코 활동 겹치기와 욕구로 고르기

> 작성일: 2026-11-18 · 상태: 설계(구현 전 사용자 확인 필요)
> 바탕: 감독 3e6e4d9·849fd83·877fb00(미용사), 엔진 62b32a9·0966b7a(헤드폰). 감독 설계는 [neko-p2-director.md](neko-p2-director.md).

## 목표

1. **겹치기(1단계).** 함께 할 수 있는 활동은 같이 한다. 예: 음악 들으며 타이핑하기, 음악 들으며 신문 읽기.
   - 활동끼리만이 아니다. 기본 상태(돌아다니기·앉기·식빵)에도 얹는다. 예: 헤드폰 낀 채 돌아다니기.
   - 조합을 손으로 적지 않는다. 활동마다 "몸의 어디를 쓰는지"를 선언하고, 함수 하나가 두 선언을 보고 같이 할 수 있는지 정한다.
2. **고르기(2단계).** 혼자 놀 때 무엇을 할지 숨은 욕구 점수로 고른다(심즈 방식).
   - 새 활동은 선언에 "무엇을 채워 주는지"만 적으면 된다. 감독 코드는 안 고친다.

두 단계는 따로 구현하고 따로 확인한다. 2단계는 1단계 위에 얹는다.

## 지금 모양

- 엔진은 활동을 **하나만** 한다(`cat.act`). `act(key)` 로 바꾸면 소품이 쏙 들어가고 새 소품이 뿅 나온다.
- 활동 하나 = `defineActivity(key, spec)` 하나. 지금 22개다:
  draw · music · butterfly · snack · stretch · typing · reading · stamp · groom · knead · yarn · giftplay · box · window · think · wait · meal · hungry · dig · calendar · erase · climb.
- `spec.pose(A, ramp)` 가 매 프레임 자세 객체를 돌려준다. 엔진은 그 키를 읽어 몸·다리·머리·귀·꼬리를 움직인다(§1.3 표).
- 감독(`derive.ts`)이 층 순서대로 활동 하나를 고른다.
  - 혼자 놀기는 `pickSolo(직전, 선물 있음)` 로 `SOLO` 12개 중 하나를 고르게 뽑는다. 부르는 곳은 `useNekoDirector.ts` 한 곳이다.
  - 다른 앱 따라 하기(`ambient.ts`)는 음악이 나오면 `outside.activity = "music"` 으로 둔다. 그래서 다른 앱에서 타이핑하는 동안에는 음악 듣기가 안 보인다(타이핑 층이 이긴다).

## 1부. 겹치기 (1단계)

### 1.1 주 활동, 곁들임, 기본 상태

- **주 활동**은 하나다. 지금의 `act(key)` 그대로다. 몸 자세·소품 자리·돌아다니기를 정한다.
- **곁들임**은 0개 또는 1개다. 주 활동 위에도 얹히고, **주 활동이 없을 때의 기본 상태** 위에도 얹힌다.
- **기본 상태**는 활동이 없을 때 고양이가 하는 일이다. 넷으로 나눈다.

  | 키 | 무엇 |
  |---|---|
  | `base:stand` | 서기·걷기·돌아다니기·마우스 따라 보기. 잡힘·점프·착지 같은 잠깐 상태도 여기에 든다 |
  | `base:sit` | 앉아 있기 |
  | `base:loaf` | 식빵(졸기 포함) |
  | `base:lie` | 누워 자기 |

- 처음 곁들임이 되는 활동은 **음악 듣기 하나**다. 음악은 두 가지로 쓴다.
  - 주 활동: 앉아서 고개를 까딱이며 듣기. 지금 모양 그대로다.
  - 곁들임: 헤드폰을 낀 채 다른 일을 한다. 걷기, 식빵, 타이핑, 나비 쫓기 같은 일이다. 사용자 요구: "노래는 돌아다니면서도 들을 수 있다".

### 1.2 부위

부위는 일곱 개로 정한다. 매니저 안 그대로다.

| 부위 | 키 | 무엇 |
|---|---|---|
| 몸 | `body` | 서기·앉기·식빵·눕기, 몸 기울기·높이·눌림 |
| 이동 | `move` | 걸어 다니기·뛰기·벽 타기 |
| 앞발 | `paws` | 앞발 자리(붓 쥐기, 키 누르기, 세수…) |
| 머리 | `head` | 머리 자리·갸웃, 시선, 표정·눈꺼풀 |
| 귀 | `ears` | 귀 각도 |
| 입 | `mouth` | 먹기·핥기·물기 |
| 꼬리 | `tail` | 꼬리 모양 |

- 표정과 눈꺼풀은 머리에 넣는다. 따로 떼어도 지금은 얻는 게 없다. 곁들임이 표정을 바꾸지 않기 때문이다(§1.6).
- 입과 이동은 자세 키가 없다. 차지했는지만 본다.

### 1.3 자세 키 → 부위

엔진이 읽는 `pose()` 키를 모두 부위에 나눈다. 조합기는 이 표로 "누구의 값을 쓸지"를 정한다.

| 부위 | pose 키 |
|---|---|
| 몸 | `sit` `loaf` `tilt` `dy` `sq` `pos` `bend` `bendW` |
| 앞발 | `feet` `feetW` `reach` `pawFront` `pawBeans` |
| 머리 | `head` `tt` `look` `expr` `lid` |
| 귀 | `ear` |
| 꼬리 | `tail` |

이 표에 없는 키가 `pose()` 에 생기면 QA 가 실패한다(§1.11).

### 1.4 선언 형식

선언은 **엔진 밖의 순수 모듈** `src/neko/engine/activity-mix.js` 에 둔다. `.d.ts` 와 테스트를 같이 둔다.

- 감독도 같은 선언과 같은 함수를 써야 한다.
- 감독이 엔진에 물어보면 안 된다. 화면 모드에선 엔진이 다른 창에 있어서, 대리 컨트롤러는 값을 바로 돌려줄 수 없다.
- 그래서 선언은 데이터로 따로 두고, 엔진과 감독이 둘 다 import 한다.

부위마다 쓰는 정도는 둘이다.

- **차지함(`hold`)**: 그 부위 값은 이 활동이 정한다. 둘이 같이 차지하면 같이 못 한다.
- **얹음(`ride`)**: 비어 있으면 자기 값을 쓴다. 다른 쪽이 차지하면 양보하고, `overlay()` 가 있으면 그 차이만 더한다.

```js
// src/neko/engine/activity-mix.js
export const PARTS = ["body", "move", "paws", "head", "ears", "mouth", "tail"];

export const MIX = {
  typing: { hold: ["body", "paws", "head", "tail"], ride: ["ears"], stance: "sit", slots: ["floor"] },
  music: {
    hold: ["ears"],                   // 헤드폰이 귀를 누른다
    ride: ["head", "tail", "body"],   // 고개 까딱·꼬리 박자·몸 통통
    stance: "sit",                    // 주 활동일 때는 앉아서 듣는다
    role: "both",                     // 주 활동도, 곁들임도
    slots: ["head"],
    with: "음악 들으며",
    notWith: ["base:lie"],            // 누워 깊이 잘 때는 벗는다
  },
  "base:stand": { hold: ["body", "move"], ride: ["head", "ears", "tail"], stance: "move" },
  "base:sit":   { hold: ["body"], ride: ["head", "ears", "tail"], stance: "sit" },
  "base:loaf":  { hold: ["body"], ride: ["head", "ears", "tail"], stance: "loaf" },
  "base:lie":   { hold: ["body", "head"], ride: ["ears", "tail"], stance: "lie" },
  // … 22개 모두(§1.9)
};

/** 감독의 계획 자세 → 기본 상태 키 */
export const baseOf = (pose) => `base:${pose}`;   // stand · sit · loaf · lie
```

| 필드 | 뜻 | 없으면 |
|---|---|---|
| `hold` | 차지하는 부위 | `[]` |
| `ride` | 얹는 부위(§1.6) | `[]` |
| `stance` | 이 활동의 몸 자세: `sit` · `loaf` · `stand` · `move` · `lie` | `stand` |
| `needs` | 곁들임으로 얹힐 때, 아래쪽(주 활동이나 기본 상태)의 `stance` 가 이 중 하나여야 한다. 지금은 쓰는 활동이 없다 | 아무 자세 |
| `slots` | 소품 자리: `floor`(앞 바닥) · `wall`(벽·창) · `air`(공중) · `head`(머리에 씀) · `decor`(놓인 선물) | `[]` |
| `role` | `main`(주 활동만) · `both`(곁들임도) | `main` |
| `with` | 곁들일 때 상태 글자 앞말 | — |
| `notWith` | 부위로는 되지만 보기 어색해서 같이 안 하는 활동·기본 상태 | `[]` |
| `fills` · `solo` | 2단계(§2.3) | — |

- **선언이 없는 활동은 "전부 차지함"이다.** 지금처럼 혼자 한다. 시안 하네스의 `wave` 처럼 밖에서 더한 활동도 그렇다.
- 엔진 `defineActivity` 의 spec 에는 `mix` 를 넣을 수 있다. 엔진은 `spec.mix ?? MIX[key] ?? 전부 차지함` 순서로 쓴다.
- **귀는 대부분의 활동에서 얹음(○)이다.** 활동들이 정하는 귀 각도는 표정을 조금 보태는 정도다(−0.15~0.22). 헤드폰을 쓰면 띠가 귀를 누르니 귀는 음악이 정하는 게 맞다. 그래서 음악만 귀를 차지한다.
- 얹는 부위가 있는 활동은 spec 에 `overlay(A, ramp)` 를 더한다. 얹을 때 더할 값(차이)을 돌려준다. 이 함수는 엔진 안의 코드다(박자·걸음 같은 엔진 상태를 쓴다).

```js
defineActivity("music", {
  // … 지금 그대로(start·step·pose). pose() 는 '앉아서 듣기'이고, 곁들일 땐 귀(ear 0.22)만 가져간다 …
  overlay(A, ramp) {
    const c = cat, walking = c.mode === "walk";
    // 걸을 땐 박자를 걸음에 싣는다: 한 걸음에 고개가 한 번 까딱. 앉아 있으면 96 BPM
    const beat = Math.max(0, Math.sin(walking ? c.gait * TAU * 2 : A.t * 1.6 * TAU));
    return { tt: (walking ? 0.05 : 0.09) * beat * ramp, sq: walking ? 0 : -0.025 * beat * ramp, tail: 6 * beat * ramp };
  },
});
```

- 걷는 동안 음표는 조금 줄인다. 앉아 있으면 0.62초마다, 움직이면(걷기·돌아다니는 활동) 1.1초마다 하나다.

### 1.5 조합기: 같이 할 수 있나

`mixable(on, side)` → `{ ok, why }`. `on` 은 주 활동 키이고, 주 활동이 없으면 기본 상태 키다. 순수 함수이고 엔진 상태를 안 쓴다. 아래 순서로 처음 걸리는 이유를 돌려준다.

1. 같은 활동이면 불가(`why: "같은 활동"`).
2. 곁들임의 `role` 이 `both` 가 아니면 불가(`"곁들임 아님"`).
3. 어느 한쪽의 `notWith` 에 상대가 있으면 불가(`"같이 안 함"`).
4. **둘 다 차지하는 부위**가 있으면 불가(`"부위: 앞발·머리"`).
   - 차지함 + 얹음은 된다. 얹음 + 얹음도 된다.
5. 곁들임에 `needs` 가 있고 `on` 의 `stance` 가 그 안에 없으면 불가(`"자세"`).
6. 소품 자리가 겹치면 불가(`"소품 자리: floor"`).

곁들임으로 얹힌 음악은 표정·눈을 바꾸지 않는다. 그래서 신문을 읽으면 눈은 줄을 따라가고, 고개만 박자에 까딱인다.

### 1.6 자세 합치기

`mergePose(on, side, onPose, sidePose, sideOverlay)` → 자세 하나. 이것도 같은 순수 모듈에 둔다. 기본 상태는 `pose()` 가 없다. 그래서 `onPose` 는 비어 있고, 그 부위는 엔진 기본값을 쓴다.

1. 부위마다 **차지한 쪽**의 pose 키를 쓴다.
2. 아무도 차지하지 않은 부위는 아래쪽(`on`) 값을 쓴다. 그것도 없으면 엔진 기본값을 쓴다.
3. 차지하지 못한 쪽의 `overlay()` 값은 새 키 `add` 에 모은다. 예: `add: { tt, sq, ear, tilt, dy, tail }`.
4. 엔진은 각 값을 다 정한 **뒤에** `add` 를 더한다. 아래쪽이 그 키를 정했든 안 정했든 같다. 고칠 곳은 여섯 군데다.
   - `tt`(머리 갸웃)·`ear`(귀)·`sq`(몸 눌림)·`tilt`(몸 기울기)·`dy`(몸 높이)·`tail`(꼬리 끝 각도, 도).

키별 규칙을 따로 두지 않는다. "차지한 쪽 값 + 얹은 쪽 차이" 하나면 된다.

예:
- **타이핑 + 음악**: 몸·앞발·머리·꼬리는 타이핑 값을 쓴다. 두 발로 톡톡 치고 눈은 화면을 본다. 귀는 음악 값(0.22, 헤드폰에 눌림)을 쓴다. `add` 에는 고개 까딱·몸 통통·꼬리 박자가 들어간다.
- **걷기 + 음악**: 몸·이동은 걷기 그대로다. 귀는 음악 값을 쓴다. `add` 에는 걸음마다 고개 까딱과 꼬리 박자가 들어간다.
- 엔진은 주 활동이 없고 곁들임만 있을 때도 이 합친 자세를 `cat.actP` 에 둔다. 지금은 `act` 모드일 때만 둔다.

### 1.7 소품

- 곁들임의 소품은 곁들임 자기 목록에 둔다. 뿅 나오고 쏙 들어가는 것도 각자 한다.
- 소품 층을 하나 더한다: **쓰는 소품 `kit.wear`**. 몸에 걸치는 것(헤드폰)이다.
  - 그리는 순서: 뒤 소품 → 고양이 → **쓰는 소품** → 앞에 내민 앞발(`pawFront`) → 앞 소품(주 활동 → 곁들임) → 효과.
  - 헤드폰은 머리 바로 위에 그려지고, 상자 앞벽·그릇 같은 앞 소품에는 가려진다. 상자 안에 머리를 넣으면 헤드폰도 같이 가려진다.
  - 상자 밖으로 내민 앞발도 헤드폰보다 앞에 보인다.
  - 이젤·노트북·신문·달력은 뒤 소품이라 순서와 상관없다.
- 음악은 주 활동일 때도 곁들임일 때도 `kit.wear` 를 쓴다.
- 소품 자리가 겹치는 조합은 §1.5 의 6번에서 이미 막힌다. 따라서 바닥 소품 두 개가 겹쳐 그려지는 일은 없다.

### 1.8 엔진 동작

| 경우 | 동작 |
|---|---|
| `mix(key)` | 곁들임을 시작한다. 지금 도는 것(주 활동, 없으면 기본 상태)과 `mixable` 이 아니면 거절한다. 거절하면 `false` 를 돌려주고 `"side"` 이벤트는 `null` 이다. |
| `mix(null)` | 곁들임을 끝낸다(소품이 쏙 들어간다). |
| 주 활동이 바뀌거나 끝남 | 새 주 활동과, 주 활동이 없으면 기본 상태와 되는지 다시 본다. 되면 이어 간다(헤드폰 그대로). 안 되면 곁들임을 끝낸다. |
| 기본 상태가 바뀜 | 같은 규칙이다. 식빵으로 졸 때는 헤드폰을 낀 채 존다. 누워 자기가 되면 헤드폰을 벗는다(`base:lie` 는 같이 안 함, 사용자 확정). 다시 깨도 엔진이 저절로 다시 씌우지 않는다. 감독이 다시 보낸다. |
| `act(k)` 이고 k 가 지금 곁들임 | 곁들임을 주 활동으로 옮겨 탄다. 헤드폰이 다시 뜨지 않고, 앉아서 듣기로 바뀐다. |
| 잡기 | `keepOnGrab` 을 주 활동과 곁들임에서 따로 본다. 음악은 `keepOnGrab` 이라 잡혀도 헤드폰을 낀 채다. 잡힘은 `base:stand` 로 본다. |
| 매 프레임 | 주 활동 `step` 다음에 곁들임 `step`. `room`·`look`·`wander` 는 주 활동 것만 쓴다. |
| 상태 글자 | `with` + 주 활동 label, 주 활동이 없으면 기본 상태 글자. 예: "음악 들으며 타이핑하는 중", "음악 들으며 걷는 중", "음악 들으며 식빵 굽는 중". |
| 산책 팻말(`setAway`) | 지금처럼 `step` 이 멈춘다. 곁들임도 같이 멈춘다. |

- 주 활동이 끝나도 곁들임은 기본 상태 위에 그대로 남는다. 따라서 `"activity"` 이벤트는 지금처럼 `null` 이다. 앞선 안의 "이어받기"(곁들임이 주 활동으로 올라감)는 없앴다.

컨트롤러에 더할 것: 메서드 `mix(key | null): boolean`, 게터 `side`, 이벤트 `"side"`.

- 메서드와 게터 이름을 나눈다. 지금의 `act()` 메서드와 `activity` 게터의 짝과 같다.
- 한 이름(`side`)에 둘을 두면 객체에 같이 둘 수 없다. 대리 프록시도 `"side"` 키 하나로 메서드를 넘기면서 게터 값으로 답해야 해서 부딪힌다.

### 1.13 감독 (1단계)

1단계 감독은 **실제로 음악이 나올 때만** 곁들인다. 무작위로 곁들이는 것은 2단계에서 점수로 한다.

- `ambient.ts`: 음악을 활동에서 떼어 낸다. `OutsideState` 에 `music: boolean` 을 더한다.
  - `activity` 는 앱으로만 정한다: `own ? null : appActivity(app)`.
  - 이제 다른 앱 따라 하기에서 음악은 **주 활동이 되지 않는다.** 앞 앱에 맞는 활동이 없으면 기본 층(돌아다니기)에 헤드폰만 얹힌다.
  - 미용사가 짚은 대로, 이렇게 해야 음악이 "ambient 의 주 활동"과 "곁들임" 두 갈래로 갈라지지 않는다.
- `types.ts`: `NekoPlan.side: NekoActivity | null`(기본 `null`).
- `derive.ts`
  - 계획을 정한 뒤 마지막에 한 번 본다. `on = plan.activity ?? baseOf(plan.pose)`.
  - `outside.music` 이고 `mixable(on, "music").ok` 면 `side = "music"`.
  - 주 활동이 없는 층(졸기·누워 자기·기본 산책·힘없음·심심)도 기본 상태 키로 본다.
    - 기본 산책 + 음악 → 헤드폰 낀 채 돌아다니기.
    - 졸기(식빵) + 음악 → 헤드폰 낀 채 졸기.
    - 누워 자기 + 음악 → 헤드폰 없음.
  - 예: 다른 앱에서 타이핑 + 음악 → typing + music. 에이전트가 신문 읽기 + 음악 → reading + music. 세수 + 음악 → groom + music.
- `scheduler.ts`
  - **보낼 곁들임** = `mixable(지금 도는 것, plan.side).ok ? plan.side : null`. 이 값이 바뀔 때만 `ctrl.mix(…)` 를 보낸다.
    - 지금 도는 것 = 엔진의 활동, 없으면 `baseOf(지금 적용한 자세)`.
    - `plan.side` 는 계획의 활동으로 정한 값이다. 머무름(dwell)이 걸리면 엔진에서는 이전 활동이 돈다.
    - 그 활동과 안 맞는 곁들임을 보내면 엔진이 거절하고 `"side"` 이벤트로 `null` 을 보낸다. 스케줄러가 그걸 보고 다시 계획대로 보내면 끝없이 되풀이된다. 위 규칙이 이것을 막는다.
  - 활동이 끝났다고 보는 조건(`a === null && cur && cur.endedAt === null`)은 **그대로 둔다.**
    - 앞선 안에는 이어받기가 있었다. 그때는 발도장 + 음악에서 발도장이 끝나면 `null` 대신 `"music"` 이 와서, 이 조건을 고쳐야 했다.
    - 이어받기를 없앴으므로 발도장이 끝나면 `null` 이 온다. 곁들임은 `side` 에 남는다.
  - 엔진이 곁들임을 끝내면 `"side"` 이벤트가 온다. 누워 자기로 벗은 경우도 그렇다. 그때 위 규칙으로 다시 맞춘다.
  - 곁들임에는 머무름(dwell)을 두지 않는다. 음악 확인은 15초마다라서 깜빡이지 않는다.
- 혼자 놀기의 `SOLO` 에는 `music` 을 그대로 둔다. 앉아서 음악만 듣는 놀이다. 도구(`code.exec` 로 음악 앱을 다룸)의 음악도 주 활동 그대로다.

## 2부. 욕구로 고르기 (2단계)

### 2.1 무엇이 바뀌나

- **언제** 혼자 놀지는 지금 그대로다: 놀이 ≥ 40, 쉬는 중, 45초~2분 뒤, 2~4분 머무름, 쓰다듬기 3번이면 그만.
- **무엇을** 할지만 점수로 고른다. `pickSolo` 의 고르게 뽑기를 점수에 비례한 확률로 바꾼다.
- 일할 때 활동(도구·답 쓰기·다른 앱 따라 하기)은 도구와 앱이 정한다. 점수 대상이 아니다.
- 보이는 게이지 둘(배고픔·놀이)은 숫자도 UI 도 안 바꾼다.
  - 놀이는 "언제 놀지" 문으로 그대로 쓴다.
  - 미용사는 놀이와 호기심이 같은 일을 하면 합치자고 했다. 합치지 않는다. 놀이는 **사용자가 채우는** 보이는 게이지(놀아주기·쓰다듬기)다. 호기심은 **네코가 스스로 채우는** 숨은 게이지(창밖·산책)다. 채우는 쪽이 다르다.
- 졸음은 지금 규칙 그대로다(무활동 5분 식빵, 6분 누워 자기). 기운이 잠을 정하지 않는다. 자는 동안 기운이 찰 뿐이다.

```
모자람 u(v)   = ((100 − v) / 100)²             호기심·청결·애정
기운 균형 e   = (50 − 기운) / 50                 −1(넘침) ~ +1(바닥)
점수 U(k)     = max(0.1, 1 + 0.15·Σ fills_k[n]·u(v_n) + 0.06·fills_k[기운]·e)
확률          ∝ U(k)     (직전 활동은 뺀다, 놓인 선물이 있으면 giftplay ×2)
```

- 모자랄수록 그 욕구를 채우는 활동의 점수가 가파르게 오른다(제곱). 거의 찬 욕구는 거의 안 끈다.
- 기운은 양쪽으로 본다. 넘치면 기운을 쓰는 놀이(나비·털실·벽 타기)가 올라가고, 바닥이면 쉬는 놀이가 올라간다.
- 기본 1 덕분에 어떤 활동도 0이 되지 않는다. 가끔 엉뚱한 놀이도 나온다.

**예 1 — 기운 넘치고 심심함**(기운 80 · 호기심 40 · 청결 70 · 애정 60)

### 2.5 곁들임 고르기

- 곁들임은 점수로 고르지 않는다. **실제로 음악이 나올 때만** 헤드폰을 쓴다(사용자 확정). 1단계 규칙 그대로다.
- 곁들임도 채움은 쌓는다(§2.3). 음악을 들으며 놀면 음악의 채움도 더한다.
- 나중에 음악 말고 다른 곁들임(골골송 같은)이 생기면, 그때 점수로 얹을지 정한다.

### 2.6 저장

- 설정 키 `neko_needs` 에 `{ energy, curiosity, clean, affection, at }` 을 JSON 으로 둔다. `cat_rpg_state` 와 같은 방식이다.
- 켤 때 `at` 부터 지난 시간만큼 §2.2 의 "꺼져 있던 동안" 속도를 적용하고 바닥에서 멈춘다.
- 1분마다 갱신한다. 저절로 떨어지는 양, 지금 하는 활동(주·곁들임)의 채움, 졸기·누워 자기를 반영하고 저장한다.
- 메인 창에서만 돈다. 화면 창은 감독을 안 돌린다.

### 2.7 감독을 어떻게 바꾸나

미용사가 남긴 조건(직전 제외, 선물 가중, draw 면 `maybeDraw`, 대기·머무름 타이머 그대로)을 모두 지킨다.

- 새 순수 모듈 `src/neko/director/needs.ts`
  - `decay(state, ms, how)`: 깨어 있음 / 졸기 / 누워 자기 / 꺼져 있음.
  - `applyFill(state, key, minutes)`.
  - `score(state, decl)`.
  - `pickByNeeds(state, { last, hasGifts }, r)` → 주 활동 하나.
- 새 스토어 `useNekoNeeds`(`director/stores.ts` 옆): 불러오기·저장·1분 틱·사건 반영.
- `useNekoDirector.ts`
  - `pickSolo(lastSolo, hasGifts)` 자리를 `pickByNeeds(...)` 로 바꾼다. `box = { since, kind }` 모양은 그대로다.
  - 그 뒤 줄(draw 면 `maybeDraw`, 머무름 타이머)은 그대로다.
  - 1분 틱에서 `ctrl.activity` · `ctrl.side` · 졸림 층을 읽어 채움을 반영한다.
  - 사건을 반영한다.
    - `ctrl.on("pet")` → 애정 +3.
    - 세션 `run_start`(사용자가 보냄) → 애정 +10.
    - 밥 끝(`fedAt`) → 청결 −10.
    - 산책 귀가 → 호기심 100, 청결 −20, 기운 −15. App 의 산책 끝 자리에서 한 줄 부른다.
- `derive.ts`
  - 곁들임은 모든 층에서 1단계 음악 규칙 그대로다.
  - `SOLO` 는 `MIX` 의 `solo` 로 바꾼다. `ROAMING` 은 `stance === "move"` 로 바꿀 수 있다.
  - `DirectorInput` 에는 숨은 게이지를 넣지 않는다. 고르는 일은 지금처럼 `useNekoDirector` 의 타이머에서 하고, `derive` 는 순수하게 둔다.
- 개발 빌드에서만 보이는 게이지 화면
  - 설정 › 고양이 맨 아래(`import.meta.env.DEV`)에 둔다.
  - 넷의 막대와 숫자를 보여 준다. 칸마다 −30 / +30 버튼을 둔다.
  - "다음 혼자 놀기 확률" 상위 5개를 보여 준다.
  - `window.__nekoNeeds` 로도 읽고 쓸 수 있다.

### 2.8 처음엔 안 하는 것

- 호기심이 낮을 때 산책을 일찍 보내지 않는다. 산책 시각은 지금 규칙(정기 산책·추가 산책) 그대로다.
- 숨은 게이지를 말풍선·대사·시스템 프롬프트에 싣지 않는다.
- 일할 때 활동을 점수로 바꾸지 않는다.
- 기운으로 잠을 정하지 않는다.

## 사용자가 정할 것 (2단계)

1. **꺼져 있던 동안의 기운**: 잔 것으로 보고 오르게 할지(이 문서의 안), 그대로 둘지.
2. **숫자**: 처음 값 70, §2.2 의 속도·바닥, §2.3 의 채움 값.
3. **애정이 낮을 때**: "쳐다보기" 활동을 새로 만들지(엔진에 활동 하나 추가). 아니면 처음엔 꾹꾹이만 둘지.
4. **상자 뒤지기(dig)**: 혼자 놀기 후보에 넣을지. 호기심을 채우는 활동이라 매니저 안에 있지만, 지금은 파일 도구 활동이다.
5. **뽑는 방식**: 점수 그대로 비례(가끔 엉뚱한 놀이, 이 문서의 안)로 할지, 점수 제곱 비례(욕구를 더 뚜렷이 따름)로 할지.
