# 네코 '모니터 화면' 자리 설계

상태: 1단계·3단계(여러 모니터) 구현, 2단계는 설계. 2026-11-17.
관련 문서: `docs/neko-v26-integration.md` §2·§9·§10(§9 표의 D안이 이것), `docs/neko-p2-director.md`.

네코가 앱 안에서만 지내지 않고 맥 화면을 자유롭게 돌아다닌다. 설정에서 자리를 셋 중에 고른다.

- 패널(`sidebar`)
- 채팅 바 아래(`dock`)
- 모니터 화면(`screen`)

처음 안은 화면 맨 아래 띠에서만 걷는 것이었다. 사용자가 "화면 전체를 자유롭게"를 원해서, 1단계부터 화면 전체를 쓰는 구조로 바꿨다. 그래야 단계가 올라가도 1단계에서 만든 것을 버리지 않는다.

---

## 0. 한눈에

- **창**: 투명 창 `neko-screen` 하나가 화면 전체를 덮는다. 이 창은 거의 비어 있고 움직이지 않는다.
- **그리기**: 캔버스는 고양이 주변의 작은 사각형(약 450×340pt)뿐이다. CSS `transform` 으로 고양이를 따라 움직인다.
  - 프레임마다 바뀌는 건 이 작은 사각형뿐이라, 화면이 커도 그리기·합성 비용이 같다.
  - 위치와 그림이 같은 프레임에 같이 바뀌어서 떨리지 않는다.
- **1단계에서 하는 것**
  - 바닥(Dock 위)을 걷는다.
  - 잡아서 화면 어디든 들고 다니고, 놓으면 바닥으로 떨어진다.
- **다음 단계**
  - 창 위에 올라앉기, 벽에 붙기, 파일 물려주기(2단계)
  - 여러 모니터(3단계)
- **크기**: 고양이 크기는 설정 슬라이더로 정한다. 기본 몸길이 약 80pt.
- **항상 위에 두기**: 설정에서 켜고 끈다(기본 켬).
  - 켜면 모든 창과 전체화면 앱 위에 뜬다.
  - 끄면 모든 창 아래, 바탕화면 아이콘 위에 있다. 화면 공유나 녹화 때 끄면 된다.
- **클릭 통과**
  - 평소엔 클릭이 뒤로 지나간다.
  - Rust 가 커서 위치를 초당 30번 읽어 화면 창에 보낸다. 화면 창이 `hit(x,y)` 로 고양이 위인지 본다.
  - Rust 만 클릭 통과를 켜고 끈다. 그것도 고양이 주변 사각형 안에서만 끈다.
- **두 창 연결**: 엔진은 화면 창에만 돈다. 감독은 메인 창에 그대로 있고, 대리 컨트롤러(`remoteNeko`)가 명령을 Tauri 이벤트로 넘긴다.
- **키보드**: 고양이를 눌러도 뺏지 않는다. 화면 창은 키 창이 될 수 없는 패널이다.
- **멈춤·숨김**
  - 멈춤: 화면 잠금, 화면 보호기, 디스플레이 잠자기, 사용자 전환.
  - 숨김: 전체화면 영상·발표, 네코 캡처, 산책.
- **잠들기**: 다른 앱을 쓰는 동안엔 잠든다. 깨우는 건 NekoDesk 안의 입력과, 화면 고양이를 누르거나 잡거나 쓰다듬는 것뿐이다.
- **엔진**: 1단계부터 바꿔야 한다(§9). 엔진은 집사가 맡고, 앱 안의 네코에 영향이 없게 모두 옵션으로 한다.
- **권한**: 새 권한은 없다. 손쉬운 사용, 화면 녹화, 입력 모니터링 모두 필요 없다.

## 1. 창

- 라벨은 `neko-screen` 이다. Rust 의 새 모듈 `neko_screen.rs` 가 `glow.rs` 와 같은 방식으로 처음 쓸 때 만든다.
  - 빌더 설정: `transparent`, `decorations(false)`, `shadow(false)`, `resizable(false)`, `skip_taskbar`, `visible(false)`, `focused(false)`, `accept_first_mouse(true)`.
  - `main.tsx` 는 이 라벨을 보면 `<NekoScreen />` 을 그린다. 바탕을 투명하게 하는 `capture-window` 클래스도 붙인다.
- 창은 패널로 바꾸되, 키 창이 될 수 없는 패널이어야 한다.
  - 지금 `make_panel` 이 만드는 클래스(`NekoQuickPanel`)는 `canBecomeKeyWindow = YES` 다. 그대로 쓰면 고양이를 누를 때 화면 창이 키 창이 된다. 그러면 사용자가 치는 글자가 원래 앱이 아니라 네코에게 간다.
  - 그래서 `make_panel` 에 인자를 더해, 키 창이 못 되는 클래스(`NekoPassivePanel`)를 고를 수 있게 한다.
- 창 동작: `CanJoinAllSpaces | FullScreenAuxiliary | Stationary | IgnoresCycle`. Mission Control 썸네일과 ⌘` 순환에는 나오지 않는다.
- 레벨은 '항상 위에 두기'를 따른다. 설정을 바꾸면 `neko_screen_show` 를 다시 불러 레벨만 바꾼다.

  | 항상 위에 두기 | 레벨 | 위치 |
  |---|---|---|
  | 켬 | `STATUS_WINDOW_LEVEL`(25) | 메뉴 막대(24)·Dock(20)·전체화면 앱 위. 화면 보호기·잠금 화면 아래 |
  | 끔 | `kCGDesktopIconWindowLevel + 1` | 바탕화면 아이콘 위, 모든 보통 창 아래 |

  보통 창 레벨(0)은 쓰지 않는다. 이 앱은 활성화되지 않아서, 다른 앱을 누를 때마다 창 순서가 제멋대로 바뀐다.
- 자리
  - 창은 고양이가 있는 모니터 하나의 `frame` 전체를 덮는다. 처음과, 그 모니터가 빠졌을 때는 주 모니터다. 주 모니터는 `NSScreen.screens[0]`(메뉴 막대가 있는 화면)이다.
  - 다른 모니터로 건너가는 것은 §8 3단계.
  - 바닥은 `visibleFrame` 의 바닥, 곧 Dock 바로 위다. Dock 이 옆에 있거나 자동 숨김이면 화면 맨 아래가 바닥이다.
  - 2초마다 `frame`·`visibleFrame` 을 다시 읽는다. 바뀌었으면 창을 옮기고 엔진에 새 바닥을 준다.
- 화면 창은 닫지 않고 숨긴다(`orderOut`). 패널로 바꾼 창을 닫으면 앱이 죽었다(`capture.rs` 머리말).
- ⌘H 로 앱을 숨겨도 화면 창은 남는다(`setCanHide: NO`). 마당의 고양이와 선물이 그대로 보이고, 눌러도 앱이 다시 나타나지 않는다(활성화하지 않는 패널). 방·거실의 네코는 메인 창 안이라 같이 숨는다.
- `capabilities/default.json` 의 `windows` 에 `neko-screen` 을 더한다.

## 2. 그리기: 작은 캔버스가 고양이를 따라간다

- 엔진의 세계는 화면 전체다. 엔진 좌표가 곧 창 좌표(왼쪽 위 원점, 포인트)다.
- 캔버스는 고양이 주변 600×440 단위만 덮는다. 기본 크기에서는 약 450×340pt, DPR 2 면 약 0.6M 픽셀이다.
  - 띠 안의 3024×400px(1.2M)보다 작고, 화면이 넓어도 그대로다.
- 엔진이 매 프레임 같은 순서로 두 가지를 한다.
  1. 그리기 영역을 고양이 둘레로 다시 잡고(고양이가 영역의 아래쪽 70% 지점에 오게), 캔버스의 `style.transform` 을 그만큼 옮긴다.
  2. 영역 원점만큼 옮겨서 그린다.
  - 둘이 같은 rAF 안에서 일어나서, 그림과 자리가 어긋나지 않는다.
- 캔버스 밖에 그려질 수 있는 것은 고양이 가까이로 묶는다. 나비는 지금 무대 전체를 날아다닌다(§9 E1).
- 고양이 크기는 높이에서 정하지 않고 고정값으로 준다. 설정의 '크기' 슬라이더로 S 를 0.55~1.4 사이에서 고른다. 0.55 면 몸길이 약 56pt, 0.8 이면 약 80pt(기본), 1.4 면 약 114pt 다. 써 보고 필요 없으면 뺀다.
- 비어 있는 화면 전체 창 자체는 그리지 않으니 비용이 거의 없을 것으로 본다. 다만 그 아래에서 영상이 돌 때 합성 부담이 있는지는 QA 에서 잰다.
  - 부담이 크면 다른 안으로 바꾼다: 창 자체를 고양이 크기로 만들어 고양이를 따라 옮긴다.
  - 이 방식은 창 자리와 그림이 따로 바뀌어 떨릴 수 있어서 처음 안으로 고르지 않았다.

## 3. 클릭 통과

화면 창은 처음에 `ignoresMouseEvents = YES` 로 뜬다. 투명한 곳만 클릭을 흘리는 macOS 기본 동작은 웹뷰 창에선 안 된다. 웹뷰 창은 투명한 곳의 클릭도 받는다.

### 커서 읽기: Rust 폴러

- 스레드 하나가 33ms(초당 30번)마다 메인 스레드에서 다음을 읽는다. `capture.rs` 의 `FOLLOW_EVERY` 와 같은 방식이다.
  - `NSEvent.mouseLocation`
  - `pressedMouseButtons`
  - `modifierFlags`
- 커서가 화면 안에서 움직였으면 `neko-screen-cursor {x, y}` 를 보낸다. 좌표는 창 기준 포인트로, 엔진 좌표와 같다.
- '항상 위에 두기'가 꺼져 있으면, 다른 창에 가려진 자리의 커서는 고양이 위로 치지 않는다. 그러지 않으면 창 너머로 고양이가 쓰다듬어진다.
  - 커서가 그리기 영역 안에 있는 동안만 0.2초마다 보통 창 목록(`capture::macos::windows()`)을 읽어서 본다.
  - `windowNumberAtPoint` 는 쓸 수 없다. 우리 창은 거의 늘 클릭 통과 상태라, 이 함수가 우리 창을 건너뛴다.
- 엔진이 멈춰 있으면(§5) 33ms 폴링도 멈춘다. 2초마다 하는 검사만 남는다.
- 다른 방법을 안 쓰는 까닭
  - 전역 이벤트 모니터는 블록·관찰자 코드가 더 들고, 우리 창이 클릭을 받기 시작하면 이벤트가 끊긴다.
  - 30Hz 폴링 비용은 30fps 그리기에 비하면 아주 작다.
  - 같은 방식이 `capture.rs` 에서 이미 돌고 있다.

### 고양이 위인지 판단: 화면 창

- 커서 이벤트를 받을 때와, 커서가 이 화면에 있는 동안 33ms 마다 `over = ctrl.hit(x, y)` 를 구한다.
  - 커서가 가만있어도 고양이가 그 밑으로 걸어오거나 떠나기 때문이다.
- `over` 가 바뀌면 바로, 참인 동안엔 0.1초마다 `invoke("neko_screen_catch", { on })` 를 보낸다.
- 쓰다듬기(`useTrackpadPet`)도 이 좌표의 차이로 센다. 키 창이 아닌 패널에선 웹뷰가 `mousemove` 를 못 받을 수 있어서, 웹뷰 이벤트에 기대지 않는다.

### 켜고 끄기: Rust 만

`ignoresMouseEvents` 는 Rust 만 바꾼다(`WebviewWindow::set_ignore_cursor_events`). 값이 바뀔 때만 부른다. 화면 창이 클릭을 받는 조건은 아래 셋을 모두 만족할 때다.

1. 마지막 `catch(true)` 를 받은 지 250ms 가 안 지났다.
   - 화면 창이 멈추면 0.25초 안에 다시 클릭이 지나간다.
2. 커서가 고양이가 있는 모니터(창이 붙은 모니터) 위에 있다.
3. ⌥ 를 누르고 있지 않다. 고양이 밑의 버튼을 누를 땐 ⌥ 를 누르면 된다.

고양이를 잡고 있는 동안(받는 중에 버튼을 누름)은 위 조건을 보지 않는다. 화면 어디로 끌어도 놓을 때까지 받는다.

처음 안엔 '화면 창이 알려 준 그리기 영역 안에서만 받기'도 있었다. 뺐다. 영역도 같은 화면 창이 알려 주니, 화면 창 판단이 틀렸을 때 막아 주지 못한다. 화면 창이 굳는 경우는 250ms 조건이 막는다.

버튼을 누른 채로 들어오면 받지 않는다. 다른 앱에서 창이나 글을 끌다가 고양이 위를 지나가는 경우다. 예외는 파일 끌기다(§7).

클릭을 받기 시작하면 진짜 마우스 이벤트가 웹뷰에 온다. 그래서 탭(쓰다듬기), 두 번 탭('냥'), 끌기(목덜미 잡기)는 엔진의 지금 처리를 그대로 쓴다. 다만 좌표는 세계 좌표로 읽어야 한다(§9 E4).

- **지연**: 커서가 고양이 위에 올라간 뒤 받기 시작할 때까지 최대 약 33ms 에 IPC 시간이 더 걸린다. 그 사이에 누른 클릭은 뒤 앱으로 간다. 받아들인다.
- **첫 클릭**: 키 창이 아닌 패널이라 `accept_first_mouse` 를 켠다. 끄면 첫 클릭을 창 활성화에 써 버린다.

## 4. 두 창 연결

엔진은 화면 창에만 둔다("네코는 앱에 하나"). 감독은 메인 창에 그대로 둔다.

- 메인 창이 안 보여도(⌘H·닫기 버튼·가려짐) 감독이 돌아야 한다. WKWebView 는 기본으로 안 보이는 웹뷰를 멈춘다 — 재 보니 ⌘H 하거나 다른 창에 다 가려지면 몇 초 뒤 타이머가 아예 멎었다. 그래서 메인 창은 `backgroundThrottling: "disabled"`(macOS 14+)다. 숨긴 동안 타이머는 2초 간격으로 줄지만 멈추지 않는다.

- 감독의 입력은 모두 메인 창 스토어에 있다. 세션 상태, 앱 상황, 배고픔·놀이, 상자가 그렇다.
- 감독을 옮기면 이 스토어를 다 동기화해야 한다. 그래서 컨트롤러만 대리로 바꾼다. 대리가 할 일은 메서드 10개와 이벤트 7개다.

### 메인 창에서 화면 창으로: `neko-cmd`

- `nekoHost` 는 다음 두 조건이 모두 맞을 때 `useNekoController()` 로 `remoteNeko` 를 준다.
  - 자리가 `screen` 이다.
  - 화면 창이 `neko-screen-ready` 를 보냈다.
- 컨트롤러가 바뀌면 `useNekoDirector` 의 effect(의존성 `[ctrl]`)가 다시 돈다.
  - 새 스케줄러가 기분·자세·활동·산책 계획을 처음부터 다시 적용한다.
  - `setTheme`·`setNeeds` effect 도 다시 돈다.
- `nekoHost` 는 대리를 만들 때 `setAppearance(현재 외형 전체)` 를 한 번 보낸다.
- `remoteNeko` 가 구현하는 것: `SchedulerCtrl`, `setAppearance`, `setNeeds`, `setTheme`, `on`. 메서드를 부르면 `emitTo("neko-screen", "neko-cmd", { m, args })` 를 보낸다.
  - `activity` getter: 스케줄러가 동기로 읽는다. `act()` 를 부를 때 바로 값을 바꿔 두고, 화면 창에서 오는 `activity` 이벤트로 바로잡는다.
  - `react()`: `true` 를 돌려준다. 반환값을 쓰는 곳은 `NekoSlot` 의 문지르기뿐인데, 화면 모드에선 화면 창이 문지르기를 직접 한다.
- 메인 창의 로컬 엔진은 `pause()` 한다. 패널이나 채팅 바 아래로 돌아오면 `NekoSlot` 이 이미 `resume()` 을 부른다.
- 자리를 바꾸면 하던 활동·자세는 이어지지 않는다. 스케줄러가 지금 계획을 바로 다시 그린다.

### 화면 창에서 메인 창으로: `neko-evt`

- 엔진 이벤트 `pet`, `nyang`, `annoyed`, `grab`, `drop`, `activity`, `error` 를 `emitTo("main", "neko-evt", { ev, payload })` 로 넘긴다.
- 메인 창은 `remoteNeko.on(...)` 으로 받는다. 지금과 같은 곳으로 간다.
  - 감독의 `ctrl.on("pet")` 은 놀이 게이지(`handlePet`)로 간다.
  - 스케줄러의 `grab`·`drop`·`activity` 도 지금 경로 그대로다.
- 문지르기는 화면 창이 로컬 엔진의 `react("pet")` 를 부르고, 고양이가 좋아했으면(`true`) `pet` 을 보낸다.
- `pet`, `nyang`, `annoyed`, `grab` 을 받으면 메인 창은 `useNekoApp.getState().markActive()` 도 부른다.
  - 화면 고양이를 만지는 것도 '앱을 쓰는 중'으로 친다. 자던 고양이가 깨고, 5분 졸음 시계가 다시 시작한다.
  - 다른 앱에서 하는 입력은 세지 않는다.
- 명령과 이벤트는 많아야 초당 몇 개라 이벤트 비용은 문제가 안 된다.

## 5. 멈춤·배터리

| 상황 | 신호 | 동작 |
|---|---|---|
| 화면 잠금 | `CGSessionCopyCurrentDictionary` 의 `CGSSessionScreenIsLocked` | 엔진 `pause`, 33ms 폴링 멈춤 |
| 사용자 전환 | 같은 사전의 `kCGSessionOnConsoleKey` 가 거짓 | 위와 같음 |
| 디스플레이 잠자기 | `CGDisplayIsAsleep(CGMainDisplayID())` | 위와 같음 |
| 화면 보호기 | 맨 앞 앱이 `com.apple.ScreenSaver.Engine` | 위와 같음 |
| 고양이가 다 가려짐('항상 위' 끔) | 그리기 영역이 보통 창 하나 안에 다 들어감 | 위와 같음 |
| 시스템 잠자기 | 프로세스가 통째로 선다 | 할 일 없음. 깨어난 뒤 첫 프레임 간격은 엔진이 0.1초로 자른다 |
| 전체화면 영상·발표 | 아래 두 조건이 모두 참 | 창을 숨기고 엔진을 멈춘다. 조건이 풀리면 다시 띄운다 |

전체화면 영상·발표로 보는 조건:

1. 고양이가 있는 모니터에 걸친 맨 앞 보통 창(layer 0)이 그 모니터 `frame` 전체를 덮는다. `capture::macos::windows()` 에서 그 모니터에 걸친 첫 항목이다(앞에서부터 나온다).
2. 그 창의 주인이 화면 꺼짐 막기를 쥐고 있다.
   - 주인은 `kCGWindowOwnerPID` 로 안다. 지금 `Target` 에는 이 값이 없어 한 칸 더한다.
   - 화면 꺼짐 막기는 `IOPMCopyAssertionsByProcess` 로 그 PID 에 `PreventUserIdleDisplaySleep` 이 있는지 본다.

- 이 검사는 모두 Rust 폴러가 2초(60틱)마다 한다. 알림 관찰자 코드는 없다.
- 영상이 아닌 그냥 전체화면 앱 위에는 뜬다.
- 프레임 수는 화면 창이 정한다. 최대 프레임은 설정에서 30·60 중에 고른다(기본 60, 앱 안 네코처럼). 30fps 에선 앱 안보다 끊겨 보인다는 사용자 의견이 있었다.
  - 평소: 고른 값.
  - 졸릴 때(`setMood("sleepy")` 명령을 받았을 때): 고른 값의 절반.
  - 잡혀 있거나 떨어지는 동안: 60fps.
- 엔진이 `error` 이벤트를 내면 화면 창은 스스로 숨는다. 클릭을 막은 채 굳지 않게 하기 위해서다.

## 6. 다른 기능과 겹칠 때

- **산책(away)**
  - 1단계: 화면 창을 숨기고 엔진을 멈춘다. 돌아오면 다시 띄운다. 메인 창 사이드바엔 지금처럼 게이지·버튼만 있다. 산책은 지도 카드에서 보인다.
  - 2단계: 화면 끝으로 걸어 나가고, 돌아올 땐 걸어 들어온다.
- **네코 캡처(`capture::run`)**: 막을 띄우기 전에 화면 창을 숨기고, 끝나면 다시 띄운다. 숨기지 않으면 `-R` 영역 찍기에 고양이가 찍히고, 막의 밝기 지도에도 들어간다.
- **다른 앱의 스크린샷·화면 공유**: 고양이가 보인다. 가리고 싶으면 '항상 위에 두기'를 끈다.
  - `sharingType = none` 은 쓰지 않는다. macOS 15 부터 ScreenCaptureKit 이 이 값을 따르지 않는다는 보고가 있어 믿을 수 없다.
- **빠른 질문 창**: 같은 레벨이고 나중에 앞으로 올라오니 고양이보다 위에 뜬다. 바꿀 것 없다. 2단계에선 창이 뜨면 고양이가 고개를 든다.
- **알림 빛(glow)**
  - 클릭이 지나가는 창이라 빛이 고양이 위로 지나가고, 클릭은 고양이에게 온다. 바꿀 것 없다.
  - 2단계에선 알림 때 꼬리를 부풀린다(`startle`).
- **창과 겹칠 때**: '항상 위'가 켜져 있으면 고양이가 모든 창 위에 그려진다. 고양이가 버튼 위에 있으면 ⌥ 를 누르고 클릭하거나, 고양이를 끌어 옮긴다.

## 7. 파일 물려주기 (2단계)

사용자 아이디어다. Finder 의 파일이나 폴더를 끌어다 네코 입에 물려 주면 앱의 임시 보관함에 들어간다. 네코는 그 파일의 macOS 아이콘(문서·폴더 모양)을 입에 문다.

### 흐름

1. 화면 모드에서 파일·폴더를 끌어다 네코 입 근처에 놓는다.
2. 파일이 임시 보관함에 들어가고, 네코가 그 아이콘을 문다. 여러 개면 최대 3장을 겹쳐 문다(개수 표시는 없다, 아래 '입에 물기').
3. 네코 입에서 아이콘을 끌어 Finder 나 다른 앱에 놓으면 그 파일이 건너간다. 놓고 나면 네코 입은 빈다.
4. 앱 안의 보관함 목록에도 그대로 보인다. 입에서 끌어 보내도 보관함에선 지우기 전까지 남는다(지금 Shelf 와 같다).

### 끌어다 놓기를 받는 방법

- 클릭 통과 중인 창은 끌어다 놓기도 받지 않고 뒤로 흘린다. 그래서 파일을 끄는 동안에도 고양이 근처에서만 클릭 통과를 끈다.
- **끄는 중에도 폴러는 돈다.**
  - 끌기는 Finder 프로세스에서 진행되고, 우리 메인 스레드는 비어 있다.
  - `mouseLocation`·`pressedMouseButtons` 는 끄는 중에도 읽힌다.
- **파일을 끄는 중인지 알기**
  - 버튼이 눌린 뒤 끌기 페이스트보드(`NSPasteboard pasteboardWithName: NSPasteboardNameDrag`)의 `changeCount` 가 바뀌었으면 무언가를 끄는 중이다.
  - 내용은 읽지 않는다. `changeCount` 만 본다. 다른 앱의 페이스트보드 내용을 읽으면 macOS 개인정보 알림이 뜰 수 있다.
  - 창을 끌거나 글을 고르는 중이면 `changeCount` 가 그대로라서 받지 않는다(§3).
- 끄는 중이면 화면 창은 커서가 받는 자리 안에 있을 때 `catch(true)` 를 보낸다. 받는 자리는 고양이 몸(`hit`) 또는 입 둘레 반지름 50 단위다. Rust 는 '버튼을 누른 채 들어오면 받지 않는다' 대신 이걸 따른다.
- **놓은 것은 Tauri 기본 끌어다 놓기로 받는다.**
  - 화면 창은 `dragDropEnabled` 를 켠다. 메인 창과 반대다.
  - Tauri 의 `DragDropEvent`(`Enter`·`Over`·`Drop`·`Leave`, 경로와 위치 포함)를 받는다. 웹뷰 HTML 드롭이 아니어서 **경로**가 오고 폴더도 받는다.
  - `Enter` 에서 고양이가 귀를 세우고 입 쪽을 본다(`react("greet")`).
  - 파일이 아니면 받지 않는다(Tauri 가 거절한다). 받는 자리가 작아서 다른 것을 잘못 막을 일은 거의 없다.

### 보관함에 넣기

- **복사한다.** 지금 Shelf 처럼 앱 데이터의 `shelf/` 에 복사한다.
  - 다만 바이트를 웹뷰로 나르지 않는다. 새 명령 `shelf_add_paths(paths)` 가 Rust 에서 경로로 바로 복사한다(`#[tauri::command(async)]`).
  - 지금 `shelf.rs` 의 ponytail 메모("큰 파일은 경로로 복사하게 바꾼다")도 이걸로 풀린다.
  - `std::fs::copy` 는 macOS 에서 APFS 복제(clonefile)를 먼저 시도하므로, 같은 볼륨이면 거의 즉시 끝나고 공간도 안 쓸 것으로 본다. 확인한다.
- **폴더도 받는다.** 그러려면 Shelf 를 다음처럼 넓힌다.
  - `list` 는 폴더도 내보내고, `ShelfItem` 에 `dir: bool` 을 더한다.
  - `remove` 는 폴더면 `remove_dir_all` 을 쓴다.
  - 앱 안 보관함에 HTML 로 놓는 길은 지금처럼 파일만 받는다. 웹뷰 드롭엔 경로가 없다.
- **크기 제한**: 한 번에 넣는 총량이 2GB 를 넘으면 넣지 않는다. 고양이는 고개를 돌린다(`react("sulk")`). `ponytail:` 메모로 한도를 상수로 둔다.
- **같은 파일을 두 번 넣으면** 지금 `shelf::add` 규칙을 따른다.
  - 이름과 내용이 같으면 새로 만들지 않고 있던 것을 쓴다. 고양이가 이미 물고 있으면 같은 id 라 그대로다(`carry` 는 같은 id 면 바꾼다). 꼬리 물음표로 "이미 있어"를 보인다.
  - 이름만 같고 내용이 다르면 `이름 (2).확장자` 로 따로 넣는다.
  - 폴더는 내용을 다 비교하지 않는다. 이름, 파일 수, 총 바이트가 같으면 같은 것으로 본다. `ponytail:` 메모를 단다.
- 넣은 뒤 Rust 가 `app.emit("shelf-changed")` 를 보낸다.
  - 앱 안 `Shelf` 는 이 이벤트를 받아 목록을 다시 읽는다. 지금은 처음 그릴 때와 자기가 넣고 지울 때만 읽는다.
  - 기존 `shelf_add`·`shelf_remove` 도 같은 이벤트를 보낸다.

### 아이콘

- 진짜 macOS 아이콘을 쓴다. 새 명령 `file_icon(path)` 가 `NSWorkspace iconForFile:` 로 아이콘을 얻는다.
  - 64px(32pt@2x) PNG data URL 로 돌려준다.
  - 파일 종류 아이콘이다. Quick Look 미리보기 썸네일이 아니다.
  - `msg_send` 로 부른다. `quick.rs` 의 `frontmost_app_name` 과 같은 방식이고 권한은 필요 없다.
- 아이콘은 보관함에 복사한 경로에서 얻는다. 그래야 앱을 다시 켜도 같은 아이콘을 만들 수 있다. 경로마다 메모리에 한 번만 만들어 둔다.
- 화면 창은 받은 data URL 을 `ImageBitmap` 으로 한 번 디코드해서 엔진의 물기 API 에 넘긴다.
- 같은 아이콘을 앱 안 보관함 목록과 끌기 그림(지금은 📄 이모지)에도 쓸 수 있다. 이번 범위는 아니다.

### 입에 물기: 집사의 물기 API 를 쓴다

입에 무는 동작은 직접 만들지 않는다. 집사가 선물 기능에서 만든 엔진 기능(767f20b, `neko-engine.d.ts`)을 같이 쓴다.

- `carry(items)`: 문다. 아이콘은 `{ id, kind: "image", image }` 로 넘긴다. 여럿이면 최대 3장이 겹쳐 보인다.
- `hitCarry(x, y)`: 그 점이 문 물건 위면 `"bundle"`.
- `carryRect()`: 문 물건이 그려진 사각형.
- `drop(id?)`: 입에서 뺀다(id 없으면 전부).
- `carryPress` 이벤트: 문 물건 위를 누르면 쓰다듬기 대신 이 이벤트가 온다. 끌어내기는 호스트가 시작한다.
- 누워 자거나 입을 쓰는 활동 동안엔 엔진이 물건을 바닥에 내려 둔다.

**개수 표시는 하지 않는다.** 처음 아이디어엔 "묶음에 개수 표시"가 있었다. 하지만 집사가 선물 설계에서 "문 물건은 숫자 없이 1~3장 겹침"으로 정했다(e81a985). 고양이 둘레에 글자를 안 띄우는 규칙(v26 §5.9)과도 맞는다. 몇 개인지는 앱 안 보관함 목록에서 본다.

### 입에서 끌어내기

1. 물고 있는 아이콘 위도 클릭을 받는 자리다. 화면 창의 판단은 `hit(x,y) || hitCarry(x,y)` 다.
2. 아이콘 위에서 누르면 엔진이 쓰다듬기·잡기 대신 `carryPress` 를 낸다.
3. 그러면 화면 창이 `startDrag({ item: [물고 있는 경로들], icon })` 를 부른다. `icon` 은 맨 위 아이콘이다. 이미 있는 `@crabnebula/tauri-plugin-drag` 를 쓰고, 여러 경로를 한 번에 넘긴다.
4. 끌기가 끝났을 때 결과가 놓음이면 입을 비운다(`drop()`). 취소면 계속 문다.
5. 끄는 동안 클릭 통과는 '잡고 있는 동안'과 같다. 버튼을 놓을 때까지 받는다.

- 물고 있는 상태는 메모리에만 둔다. 앱을 다시 켜면 입은 비어 있다. 파일은 보관함에 남는다.
- 새로 물려 주면 지금 묶음에 더한다. 넣은 것들만 물고 있다. 보관함 전체가 아니다.

## 8. 단계

**1단계**

- 화면 전체 창과 고양이를 따라가는 작은 캔버스
- 바닥 걷기
- 잡아서 화면 어디든 들고 다니기, 놓으면 바닥으로 떨어지기
- 클릭 통과: 폴러, 250ms 확인, 영역 제한, ⌥ 통과
- 키 창이 못 되는 패널
- `remoteNeko` 와 `neko-cmd`·`neko-evt`
- §5 의 멈춤 조건과 프레임 수 규칙
- 캡처·산책 때 숨기기
- 화면 고양이를 만지면 '앱을 쓰는 중'으로 치기
- 설정: 세 자리 고르기, '항상 위에 두기', 크기 슬라이더
- 엔진: E1~E5(§9)

**2단계**

- 파일 물려주기(§7). 물기는 집사의 `carry` API 를 쓴다
- 창 위에 올라앉기
  - 보통 창의 윗변 가운데 다른 창에 가리지 않은 부분을 발판으로 쓴다.
  - 고양이 근처에 있을 때 0.5초마다 다시 읽는다.
  - 창이 움직이면 같이 가고, 닫히면 떨어진다.
- 놓았을 때 아래에 있는 발판(창 윗변)에 떨어지기
- 화면 양 끝 벽에 붙어 있기. 지금 엔진은 매달렸다가 1초쯤 뒤 꼭 미끄러진다.
- 마우스 따라 보기·걷기, 커서가 다시 나타나면 인사(E6)
- 산책 나가기·돌아오기 걸음
- 빠른 질문 창·알림에 반응하기

**3단계: 여러 모니터** (구현함)

- 창은 계속 하나다. 고양이가 있는 모니터로 창을 옮겨 붙이고, 엔진도 하나다.
- Rust 는 2초마다 모니터 목록(`frame`·`visibleFrame`)을 읽는다. 전역 좌표는 주 모니터 왼쪽 위가 0,0 이다. 화면 창에 보내는 커서는 창이 붙은 모니터 왼쪽 위 기준이다.
- 건너가는 길은 둘이다.
  - **잡고 끌어 넘기기**: 잡고 끄는 중에 커서가 다른 모니터로 들어가면 Rust 가 바로 창을 그 모니터로 옮긴다. 고양이를 잡았을 때만이다. 화면 창이 `neko_screen_catch` 에 고양이 위인지(`cat`)도 알리고, Rust 는 누른 순간의 값으로 무엇을 잡았는지 정한다. 마당 선물을 끄는 동안엔 창이 따라가지 않고 커서를 따라 건너가기(away)도 멈춘다. 선물은 이 화면 끝에서 멈춘다.
    - 세계 이동량은 옛 창 원점 − 새 창 원점이다. 고양이가 커서 밑에 그대로 있다.
    - 끄는 중에 창이 옮겨져도 포인터 캡처는 이어진다. 다음 `clientX` 는 이미 새 좌표다.
  - **커서가 있는 모니터로 걸어가기**
    1. 커서가 다른 모니터에 3초 있으면 Rust 가 `neko-screen-away`(`"left"`·`"right"`)를 보낸다. 그 모니터 가운데가 왼쪽이면 left, 아니면 right 다. 위아래로 놓였으면 right 다.
    2. 고양이가 한가하면(잡혀 있지 않고 활동이 없으면) 화면 창이 `walkOut(side)` 를 부른다. 활동 중이면 1초마다 다시 본다.
    3. 고양이 가운데가 끝을 넘으면 엔진이 `edge` 를 보낸다. 화면 창이 `neko_screen_cross(side)` 를 부른다.
    4. 커서가 아직 그 모니터에 있으면 Rust 가 창을 옮긴다. 이동량은 오른쪽으로 나가면 (−옛 폭, 새 바닥 − 옛 바닥), 왼쪽이면 (+새 폭, 새 바닥 − 옛 바닥)이다. 새 모니터의 반대쪽 끝에서 걸어 들어온다. 모니터가 실제로 맞닿았는지는 보지 않는다.
    5. 그새 커서가 돌아왔으면 `false` 를 돌려준다. 화면 창이 `setEdges` 로 닫으면 고양이가 걸어 들어온다. 커서가 돌아와 away 가 null 이 될 때도 같다.
- 창을 옮길 때
  1. Rust 가 창을 숨긴다(alpha 0). 옮긴 자리에 옛 그림이 한 프레임 비치지 않게 하려는 것이다.
  2. 창을 옮기고 `neko-screen-moved` `{ layout, shift }` 를 보낸다.
  3. 화면 창이 `shiftWorld(shift)` → `setGround` → `setEdges(닫힘)` 을 부른다. `shiftWorld` 는 끝나자마자 한 번 그린다.
  4. 다음 프레임에 `neko_screen_reveal` 로 다시 보인다. 0.5초 안에 안 오면 Rust 가 스스로 보인다.
- 붙어 있던 모니터가 빠지면 주 모니터로 돌아간다. 세계는 옮기지 않는다. 밖에 남은 고양이는 닫힌 벽 안으로 걸어 들어온다.
- 잠자기 검사(`CGDisplayIsAsleep`)는 지금도 주 디스플레이만 본다.

## 9. 엔진에 필요한 것 (집사에게)

모두 옵션으로 켠다. 앱 안의 네코(사이드바·채팅 바 아래)는 그대로다.

1단계 E1~E5 는 집사가 f524a45 로 넣었다. 이름: `world` 옵션, `scale` 옵션, `setScale(S | null)`, `setGround(y | null)`, `region`(지금 그리는 세계 영역). 엔진이 창 크기 바뀜을 스스로 듣고, 캔버스 크기·`transform` 도 스스로 정한다. 호스트는 캔버스를 `position: fixed; left: 0; top: 0` 에 두기만 한다.

**1단계**

- **E1 세계와 그리는 영역 분리**: `world: true`.
  - 세계 크기 W·H 는 창 크기(`innerWidth`·`innerHeight`)다.
  - 캔버스는 고양이 둘레 600×440 단위만 덮는다. 매 프레임 영역을 다시 잡고, 캔버스 `transform` 과 그리기 원점을 같은 rAF 에서 바꾼다(§2).
  - 나비처럼 멀리 가는 것은 고양이 둘레 영역 안으로 묶는다.
- **E2 크기 고정**: `scale` 옵션과 `setScale(S)`. 높이로 크기를 정하지 않는다.
- **E3 바닥 지정**: `setGround(y)`. 바닥은 `H - 6` 이 아니라 `visibleFrame` 바닥이다.
- **E4 세계 좌표 입력**: 포인터 이벤트와 `hit(x, y)` 를 세계 좌표로 읽는다. 창이 곧 세계라서 `clientX`·`clientY` 를 그대로 쓰면 된다.
- **E5 높은 데서 떨어지기**: 화면 위쪽에서 놓아도 떨어지고 착지가 자연스러워야 한다.
  - 지금 `dropH > 150` 이면 꼬리를 내린다.
  - 수백 pt 에서 떨어질 때 속도 상한과 착지 반응을 맞춘다.

**3단계 (bb5d0b8)**

- `shiftWorld(dx, dy)`: 세계에 놓인 것을 모두 옮긴다. 속도·방향은 그대로다. 세계 모드에선 창 크기가 바뀌어도 고양이 자리를 두지 않고 그대로 둔다.
- `setEdges({ left, right })`: 열린 쪽은 `walkTo`·`walkOut` 으로만 넘는다. 산책·마우스 따라가기는 넘지 않는다. 닫힌 쪽 밖이면 걸어 들어온다.
- `walkOut(side)`: 그쪽을 열고 몸이 다 넘어가는 데까지 걷는다.
- `edge` 이벤트: 열린 쪽에서 고양이 가운데가 세계 밖으로 나간 순간 한 번.

**2단계**

- **E6 외부 포인터**: `pointer(x, y | null)`. 폴러 좌표를 넣어 마우스 따라 보기·인사를 살린다.
- **E7 발판**: `setPlatforms([{ id, x0, x1, y }])`. 발판 위를 걷고, 발판이 움직이면 같이 가고, 없어지면 떨어진다.
- **E8 벽에 붙어 있기**: 화면 양 끝에서 미끄러지지 않고 붙어 있는 상태.
- 파일 물려주기용 물기 API: **이미 있다**(767f20b, §7).
  - 이미지 소품: `carry({ id, kind: "image", image })`.
  - 묶음: 최대 3장 겹침, 숫자 없음.
  - 끌기 시작: `hitCarry(x, y)` 와 `carryPress` 이벤트.
  - 놓기: `drop(id?)`.
  - 다른 활동과 겹칠 때: 누워 자거나 입을 쓰는 동안 바닥에 내려 둔다.
  - 세계 모드에서도 `hitCarry`·`carryRect` 가 세계 좌표로 오는지만 확인하면 된다.

## 10. 위험

- **손쉬운 사용 권한: 필요 없다.** 쓰는 것은 모두 권한이 필요 없다.
  - `NSEvent` 클래스 메서드
  - `setIgnoresMouseEvents`
  - `CGWindowList` 의 창 위치·layer·PID. 창 이름은 안 읽어서 화면 녹화 권한도 필요 없다.
  - `CGSession` 사전, `CGDisplayIsAsleep`, `IOPMCopyAssertionsByProcess`
  - 끌기 페이스트보드의 `changeCount`. 내용은 읽지 않는다.
  - `NSWorkspace iconForFile:`
  - 새 권한 창은 뜨지 않는다.
- **App Store·서명**
  - 지금도 `macOSPrivateApi`(투명 창)와 창 클래스 바꾸기(`object_setClass`)를 쓴다. 그래서 원래 App Store 에는 낼 수 없다. 이번 일로 달라지지 않는다.
  - GitHub 릴리스·업데이터 배포에는 영향이 없다.
  - 새 entitlement 가 없고, 서명도 그대로라 TCC 가 다시 묻지 않는다.
- **다른 앱 입력을 막을 가능성**
  - 화면 전체를 덮는 창이지만, 클릭을 받는 곳은 화면 창이 `hit` 로 고양이 위라고 본 곳뿐이다.
  - 안전장치
    - 250ms 동안 '고양이 위' 확인이 없으면 Rust 가 통과시킨다.
    - 커서가 고양이가 있는 모니터 밖에 있으면 통과시킨다. 다른 모니터 클릭은 늘 그 모니터 앱으로 간다.
      - 예외: 잡고 끄는 중이면 어느 모니터든 놓을 때까지 받는다. 그러다 다른 모니터로 들어가면 창도 그리로 옮긴다.
    - 버튼을 누른 채 들어오면 받지 않는다. 파일 끌기만 예외다.
    - ⌥ 를 누르면 통과한다.
    - 엔진 오류가 나면 창을 숨긴다.
    - 키 창이 못 되는 패널이라 키보드는 뺏지 않는다.
- **확인이 필요한 것**
  - 키 창이 아닌 패널에서 `accept_first_mouse` 를 켰을 때 웹뷰가 첫 `pointerdown` 을 받는지.
  - 끌기 도중 `ignoresMouseEvents` 를 바꾸면 끌어다 놓을 대상 판정에 바로 반영되는지.
  - `tauri-plugin-drag` 의 `startDrag` 가 키 창이 아닌 패널에서 되는지.
  - 앱이 비활성일 때 햅틱(`haptic_feedback`)이 울리는지. 안 울려도 쓰다듬기는 된다.
  - 비어 있는 화면 전체 투명 창이 그 아래 영상 재생의 합성 부담을 늘리는지(§2).
- **메모리**: 웹뷰 프로세스가 하나 더 뜬다. 화면 모드를 처음 고를 때 만든다. QA 에서 잰다.
- **`CGSSessionScreenIsLocked`** 는 문서에 없는 키다. 없어지면 잠금 중에도 그리지만, 디스플레이 잠자기 검사가 대부분 같이 잡는다.

### QA(1단계)

- 클릭 통과
  - 화면 아무 데서나 Finder·브라우저의 클릭, 스크롤, 끌기가 그대로 되는지. 메뉴 막대와 Dock 도 본다.

- 잡아서 화면 위쪽까지 들고 가 놓으면 바닥으로 떨어지는지. 그림이 떨리거나 잘리지 않는지.
- 고양이를 누른 뒤 글자를 치면 원래 앱에 들어가는지.
- 전체화면 앱 위, Space 넘기기, Mission Control 에서 어떻게 보이는지.
- 잠금, 화면 보호기, 디스플레이 잠자기 동안 CPU 가 0 근처인지. 풀린 뒤 다시 움직이는지.
- 전체화면 영상(Safari, QuickTime) 동안 숨는지. 끝나면 다시 뜨는지.
- 네코 캡처의 영역 찍기에 고양이가 안 찍히는지.
- '항상 위에 두기'
  - 끄면 모든 창 아래로 가는지.
  - 창에 가려진 고양이가 그 창 너머로 쓰다듬어지지 않는지.
  - 다 가려지면 멈추는지.
- 크기 슬라이더를 움직이면 고양이 크기가 따라오는지.
- 다른 앱만 쓰면 5분 뒤 잠드는지. 화면 고양이를 누르거나 쓰다듬으면 깨는지.

## 12. 정한 것 (2026-11-17, 사용자)

1. **⌥ 로 통과**: 넣는다.
2. **다른 앱의 스크린샷·화면 공유**: 고양이가 보인다. 대신 '항상 위에 두기'를 켜고 끌 수 있게 한다(기본 켬).
   - 매니저 지시의 "화면 캡처 중엔 숨어"는 네코 캡처로 읽었다(§6).
3. **전체화면 영상으로 볼 조건**: 전체화면이면서 화면 꺼짐 막기를 쥔 앱일 때만 숨긴다.
4. **'앱을 쓰는 중'으로 칠 입력**: NekoDesk 안의 입력과, 화면 고양이를 누르기·잡기·쓰다듬기만 센다(§4).
5. **크기**: 1단계에 슬라이더로 넣어 써 보고, 필요 없으면 뺀다(§2).
6. **화면 전체를 자유롭게**: 1단계부터 화면 전체 창 + 고양이를 따라가는 작은 캔버스 구조로 간다. 엔진도 1단계부터 바꾼다.
7. **파일 물려주기**: 2단계에 넣는다(§7). 물기는 집사의 선물 기능 API(`carry`·`hitCarry`·`carryRect`·`drop`·`carryPress`)를 쓴다. 개수 표시는 집사 결정대로 하지 않는다.
