# 네코 v26 도입 설계 — 코드로 그리는 고양이 엔진

> 작성일: 2026-11-16
> 목적: 스프라이트 고양이(`CatCanvas` + `spriteData`)를 v26 '말랑 네코' 엔진으로 바꾸고,
> 상태값(배고픔·놀이·감정)·밥 주기·놀아주기·쓰다듬기·도구 사용·미니게임을 모두 새 고양이의 동작으로 연결한다.
> 기준 시안: [`docs/neko/maltang-neko-v26.html`](neko/maltang-neko-v26.html) (아티팩트 v26 과 같은 파일, 브라우저로 바로 열린다)

## 0. 한눈에

- 고양이는 **픽셀 스프라이트 → 코드로 그리는 캔버스 엔진**으로 바뀐다.
  - 뼈대: 몸통 출렁임, 2관절 IK 다리, 20마디 꼬리.
  - 무늬: 흰 반점·삼색·줄무늬·포인트를 매번 생성한다.
  - 자세 4가지, 활동 14가지, 꼬리 언어 9가지를 가진다.
- 앱은 엔진을 직접 만지지 않는다. 다음 순서로 전달된다.
  1. 앱 상태
  2. **감독(Director)** — 순수 함수 + 스케줄러
  3. **NekoController** — 엔진 API
  4. 엔진
- 감독은 테스트 가능한 순수 함수로 둔다.
- 상태는 **다섯 층**으로 나눈다.
  1. 손(잡기·낙하)
  2. 반응(꼬리 신호·하트)
  3. 활동(도구·밥·놀이)
  4. 자세
  5. 기분
- 위 층이 아래 층을 덮고, 덮개가 걷히면 아래 층이 다시 보인다.
- **도구를 쓰면 그 도구에 맞는 활동**을 한다.
  - `code.exec` → 노트북 타이핑
  - `web.search` → 창밖 구경
  - `todo.complete` → 발도장
- 결과는 꼬리 언어로 말한다.
  - 성공: 떨기 → 세우기
  - 오류: 탁탁
  - 위험 확인: 꼬리펑
- **밥 주기(= 대화 요약 compact)** 를 누르면 요약이 끝날 때까지 밥을 먹는다. 다 먹으면 핥고 웃는다.
- 배고픔·놀이 게이지는 **평소 행동**에 스며든다.
  - 배고프면 빈 그릇 앞에서 기다린다.
  - 심심하면 늘어진다.
  - 신나면 혼자 논다.
- 이식은 두 단계로 한다.
  - 1단계: 시안 엔진을 동작이 똑같게 모듈로 감싼다(회귀 테스트로 확인).
  - 2단계: 파일을 기능별로 쪼갠다.
- **고양이 주변엔 글자를 띄우지 않는다**(탁·꾹·깍깍·냠·골골·냥!·z 등). 감정은 눈·귀·꼬리·몸짓으로만 보인다(§5.9).
- 자리: **사이드바 패널, 높이를 끌어서 조절**한다(고양이 크기가 높이를 따라감). 설정에 **'채팅 바 아래로 내리기'** 토글을 두어 입력창 아래 띠로 옮길 수 있다(§9).
- 남은 결정은 [§14](#14-결정이-필요한-것)에 모았다.

### 3.3 이식 전략

1. **그대로 감싸기(P0)**
   - 시안의 IIFE 를 `createNeko(canvas, opts)` 로 감싼다.
   - 전역(`window.__neko`, DOM 칩 UI)은 컨트롤러 API 로 바꾼다.
   - 그리는 코드는 한 줄도 고치지 않는다.
   - 회귀 스크립트로 시안과 같은 결과인지 확인한다.
2. **쪼개기(P2 뒤)**
   - 동작이 묶인 뒤에 `rig/`, `coat/`, `render/`, `activities/` 로 파일을 나눈다.
   - 나눌 때마다 회귀 스크립트를 돌린다.

먼저 쪼개면 '동작이 바뀐 건지, 옮기다 깨진 건지'를 가를 수 없다. 그래서 순서를 지킨다.

### 3.4 컨트롤러 API (초안)

> 실제로 만든 API 는 [`src/neko/engine/neko-engine.d.ts`](../src/neko/engine/neko-engine.d.ts)가 기준이다.
> 아래 초안과 달라진 점:
> - `say`·`look` 은 뺐다(글자를 띄우지 않음).
> - `setQuality` 대신 `setMaxFps` 를 뒀다.
> - `react` 는 `pet·nyang·startle·greet·cheer·proud·sulk·down` 을 받는다.

```ts
interface NekoController {
  // 외형
  setAppearance(a: Partial<NekoAppearance>): void;   // 털·무늬·씨앗·눈·털 길이·귀·꼬리·체형·다리·말랑함
  // 상태
  setMood(m: "idle" | "happy" | "sleepy" | "curious"): void;
  setPose(p: "stand" | "sit" | "loaf" | "lie"): void;
  act(key: ActivityKey | null, opts?: { minMs?: number; until?: Promise<unknown> }): void;
  tail(sign: TailSign, ms?: number): void;            // 꼬리 언어 잠깐
  react(kind: "pet" | "nyang" | "startle" | "greet" | "cheer" | "sulk"): void;
  setNeeds(n: { hunger: number; play: number }): void; // 평소 행동에 스며듦(§5.4)
  look(target: { x: number; y: number } | "user" | null): void;
  // 환경
  resize(w: number, h: number, dpr: number): void;
  setTheme(t: { dark: boolean; transparent: boolean }): void;
  setQuality(q: "high" | "low"): void;                // 장모 털 다발·그림자 생략
  pause(): void; resume(): void; destroy(): void;
  hit(x: number, y: number): boolean;
  on(ev: "pet" | "nyang" | "grab" | "drop" | "activityEnd" | "annoyed", fn: (p?: unknown) => void): () => void;
}
```

## 4. 상태 모델: 다섯 층

| 층 | 정하는 곳 | 예 | 길이 | 덮는 것 |
|---|---|---|---|---|
| ① 손 | 엔진(사용자 입력) | 목덜미 잡기·낙하·점프·털기 | 입력 동안 | 전부(활동은 잠깐 멈추거나 끝남) |
| ② 반응 | 감독·엔진 | 꼬리 신호, 하트, '냥', 깜짝, 인사 | 0.5~3초 | 꼬리·귀·눈만. 활동은 그대로 |
| ③ 활동 | 감독 | 도구 사용, 밥, 놀이, 게임, 상자 | 일이 끝날 때까지(최소 머무름 있음) | 자세·기분 일부 |
| ④ 자세 | 감독 | 서기·앉기·식빵·누워 자기 | 상황이 바뀔 때까지 | 기분 일부 |
| ⑤ 기분 | 감독 | 기본·행복·졸림·궁금 + 배고픔·놀이 | 길게 | — |

규칙:
- **반응은 겹쳐도 된다.** 꼬리와 귀만 바꾸고 하던 활동은 이어 간다. 예: 타이핑하다 오류가 나면 탁탁 하면서 계속 친다.
- **손(①)이 들어오면 활동을 멈춘다.** 음악·나비·털실은 잡혀도 이어 간다(시안의 `keepOnGrab`). 놓으면 감독이 지금 상태로 다시 정한다.
- **세션 감정은 세션마다 따로 둔다.** 화면의 고양이는 활성 세션 것만 보여 준다. 세션을 바꾸면 소품은 쏙 들어가고 새 세션의 활동이 '뿅' 하고 나온다.

## 6. 감독(Director) 규칙

> 자세한 설계(신호·세션 상태·층과 우선순위·스케줄러 규칙·시간표 테스트)는 [`neko-p2-director.md`](neko-p2-director.md). 아래는 처음 잡은 틀이다.

`deriveNeko(state) → NekoPlan` 은 순수 함수다. 시간에 따른 일은 스케줄러가 맡는다.

```ts
type NekoPlan = {
  mood: Mood;
  pose: Pose;
  activity: { key: ActivityKey; reason: string } | null;
  reactions: Array<{ kind: TailSign | ReactKind; ms: number }>; // 이번 변화로 생긴 일회성 반응
  needs: { hunger: number; play: number };
  look: LookTarget | null;
};
```

스케줄러 규칙:

1. **최소 머무름 1.5초.**
   - 빨리 끝나는 도구가 연달아 와도 활동이 깜빡이지 않는다.
   - 머무는 동안 새 활동이 오면 '다음'으로만 기억하고, 머무름이 끝날 때 하나만 바꾼다(마지막 것이 이긴다).
2. **같은 활동이면 이어 간다.**
   - 타이핑 → 타이핑이면 소품을 다시 뽑지 않는다.
3. **교체는 '쏙 → 뿅'.**
   - 소품을 0.25초에 쏙 넣고, 다음 활동 소품을 '뿅' 꺼낸다.
4. **일회성 활동은 끝나면 돌아온다.**
   - 발도장·간식·기지개·벽 타기가 해당한다.
   - 끝나면 지금 계획의 활동이나 자세로 돌아간다.
   - 도구가 더 오래 걸리면 반복한다(발도장 두 번째 칸).
5. **에이전트가 끝나면 0.6초 여운**을 두고 결과 반응을 낸다. 활동은 그 뒤 정리한다.
6. **우선순위**
   - 손 > 사용자 확인 대기 > 밥 먹기 > 에이전트 활동 > 게임 > 놀이 > 배고픔·심심 행동 > 졸림 > 산책.
7. **세션 감정 저장**
   - `useAgentPool` 은 감정 하나 대신 `NekoSessionState` 를 세션마다 둔다.
   - 들어가는 값: `phase`(idle·thinking·tool·answering·waiting·done·error), `tool`, `startedAt`, `lastResult`.
   - 처음엔 `catEmotion` 과 같이 두고(호환), P2 에서 바꾼다.

테스트(`director.test.ts`)는 예를 표로 쓴다.
- 입력: 루프 이벤트 순서 + 시간
- 출력: 활동 순서 + 반응 목록

예: `step_done(web.search)` 를 0.3초에 받고 `step_done(web.scrape)` 를 0.9초에 받으면, 창밖 구경을 1.5초 한 뒤 신문 읽기로 바뀐다.

## 7. 엔진에 새로 만들 것

> P3 에서 만들었다(2026-11-17): `think`·`wait`·`meal`·`hungry`·`dig`·`calendar` + 일정 삭제용 `erase`(한 번짜리). 기상은 감독이 기지개(`stretch`) → 인사로 처리한다.
> 쓰다듬기 반응은 P1 에서 엔진에 넣었다. 회귀(`npm run qa:neko`)는 활동 21개를 모두 돈다.

| 키 | 이름 | 쓰임 | 모양 |
|---|---|---|---|
| `think` | 골똘히 | 생각 중, 끝말잇기 차례 | 앉아서 고개 갸웃(번갈아), 눈 반쯤, 꼬리 끝 까딱, 가끔 앞발로 턱 괴기 |
| `wait` | 기다림 | 확인·질문 대기, 끝말잇기 사용자 차례 | 앉아서 사용자 쪽(화면 앞)을 봄, 귀 앞으로, 꼬리 물음표, 가끔 앞발 들썩 |
| `meal` | 밥 먹기 | 밥 주기(compact) 동안 | 간식 활동의 긴 판. `until` 약속이 끝날 때까지 냠냠 반복 → 핥기 → 끝 |
| `hungry` | 빈 그릇 | 배고픔 10~30 | 빈 그릇 '뿅', 앞에 식빵 자세로 앉아 사용자 쪽 보기, 가끔 그릇 앞발로 톡 |
| `pet` (반응) | 쓰다듬기 | 클릭·트랙패드 | 손 쪽으로 머리 기울임, 웃는 눈, 볼터치, 하트 도형 효과. 과하면 짜증 게이지 |
| `dig` | 상자 뒤지기 | 파일 도구 | 상자 활동 변형: 앞발로 뒤적, 머리 넣었다 빼기, 종이 한 장 '뿅' |
| `calendar` | 달력 보기 | 일정 조회 | 발도장 소품에서 찍지 않고 시선으로 칸을 훑기 |
| `wake` | 기상 | 무활동 뒤 돌아옴 | 누워 자기 → 눈 뜨고 → 기지개(기존) |
| 꼬리 `sulk` 묶음 | — | 오류 | 탁탁 + 귀 젖힘 + 반쯤 감은 눈(이미 꼬리 언어에 있음) |

모두 `defineActivity` 모듈로 만든다(엔진 코어는 손대지 않는다). 시안에서 쓰던 회귀 스크립트로 관절 튐·뒤집힘, 소품 쫀득함, 바닥 뚫림을 확인한다.

```ts
  ear: "pointy" | "round" | "fold";
  tail: "long" | "fluffy" | "bob";

```

- **기존 사용자 옮기기**: `nekodesk_cat_variant` 를 읽어 처음 한 번만 바꾼다.

  - `gray` → 회색
  - `brown`·`white` → §14-4 결정에 따름
- **설정 모달**: '고양이' 영역엔 지금 모습 요약(색 견본 + 한 줄)과 **'네코 꾸미기' 버튼**만 둔다.
- **꾸미기 창**(`NekoCustomizeModal`): 시안 페이지처럼 위엔 미리보기 무대(따로 돌리는 엔진 하나, 닫으면 없앤다), 아래엔 고르기.
  - 한 번에 다 고르지 않고 **6단계**: 털 색 → 무늬 → 눈 색 → 체형·다리 → 털·귀·꼬리 → 말랑함·확인. 위쪽 단계 표시(아이콘, 지난 단계는 체크)를 눌러 오갈 수 있다.
  - 털 색: 기본 5색 + **직접 고르기(RGB)**: 시스템 색 고르기 창과 `#rrggbb` 입력 칸.
  - 칩마다 그림(`NekoGlyph`): 체형·다리·귀·꼬리는 **지금 모습에서 그 한 가지만 바꾼 실루엣**, 털 길이는 고양이 모양 대신 **모피 띠의 털 다발 길이**(끝이 둥근 다발을 두 겹으로), 무늬는 털 색 동그라미 위 무늬, 눈은 홍채 색 눈, 미리보기 자세도 실루엣.
  - 무늬는 겹쳐 고를 수 있다. '다시 뽑기' 버튼으로 씨앗을 바꾼다.
  - 말랑함: 값을 바꾸고 손을 떼거나 '콕 눌러 보기'를 누르면 미리보기를 콕 눌러(`boing`) 바로 차이를 보여 준다.
  - 고르면 바로 앱의 네코에도 반영·저장(0.25초 모아서). '처음대로'는 창을 열 때 모습으로 되돌린다.
- **말랑함이 바꾸는 것**(0 단단 ↔ 1 젤리): 몸통 출렁임 스프링(세기 1400→150, 감쇠 46→7.5)과 흔들림 크기, 배 처짐(바닥에 닿으면 처지지 않음), 숨쉬기 폭, 착지·콕 눌림 깊이, 목덜미 잡혔을 때 늘어남. 뛸 때 더 늘어나므로 낮은 무대에선 점프 높이 여유를 그만큼 더 둔다.
- **'채팅 바 아래로 내리기' 토글**(같은 '고양이' 탭).
  - 끄면(기본) 사이드바 패널에 있다.
  - 켜면 대화 입력창 아래 띠로 옮긴다(§9).
  - 저장 키는 `neko_stage`(`{ placement, sidebarH, dockH }`)다. 패널 높이와 함께 저장한다.
- 기분·자세·활동·꼬리 언어 칩은 시안의 개발용 UI 라서 앱에는 넣지 않는다. 개발 빌드에서만 `?neko-debug` 로 연다.

## 9. 무대(Stage) 배치와 크기 — 정함

v26 은 **걷고, 돌아앉고, 소품을 앞에 놓는** 고양이다.

- 몸 크기
  - 고양이 몸길이는 약 100단위다.
  - 시안 무대에선 단위당 약 1~1.2px 이라 몸이 100~120px 였다.
- 필요한 자리
  - 소품은 앞쪽에 50~100단위가 필요하다.
  - 머리·수염이 무대 밖으로 안 나가게, 양옆에 약 92단위씩 여백을 둔다.
- 크기 공식
  - 시안: `S = clamp(min(폭/600, 바닥높이/300), 0.55, 1.4)`, 폭이 좁으면 0.55 에 걸린다.
  - 앱: 무대 **높이로 크기를 정한다**(원하는 몸길이 기준). 폭은 산책 범위와 소품 크기만 줄인다.

| 안 | 무대 | 고양이 크기 | 장점 | 단점 |
|---|---|---|---|---|
| A. 사이드바 패널 그대로 | 220 × 150px | 단위당 0.55px(몸 약 55px). 시안 공식 그대로면 이 값 — **지금 스프라이트(104px)의 절반** | 레이아웃 그대로 | 작고, 걷기·소품 자리가 거의 없음 |
| B. 사이드바 패널 키우기 | 220~280 × 200px | 높이 기준 단위당 약 0.8px(몸 약 80px) | 자리 그대로, 크기 비슷 | 사이드바 목록 높이를 50px 덜 씀. 폭 220px 이면 양옆 여백(약 74px씩)을 빼고 걸을 수 있는 범위가 약 70px 라 걷기는 짧게, 큰 소품(이젤·노트북)은 줄여야 함 |
| C. 대화 영역 아래 '바닥' 띠 | (대화창 폭) × 140px, 입력창 위 | 단위당 약 0.9px | 넓게 걷고 활동 소품을 다 씀. 답을 쓰는 동안 바로 옆에서 타이핑 | 대화 영역을 140px 차지(접기 버튼 필요). 레이아웃 변화 큼 |
| D. 데스크톱 오버레이 창 | 화면 아래쪽 띠(투명, 항상 위) | 자유 | 진짜 데스크톱 펫. 시안의 투명 모드·`hit()` 를 씀 | Tauri 투명 창·클릭 통과·멀티 모니터 처리 필요. 1차엔 무거움 |

**정했다: 사이드바 패널(B) + 높이 조절 + '채팅 바 아래로' 토글(C).**

- **사이드바 패널(기본)**
  - 패널 위쪽 가장자리를 끌어서 높이를 바꾼다. 범위는 150~320px, 기본 200px 이다. 사이드바 폭 손잡이와 같은 방식이다.
  - 고양이 크기는 **높이로** 정한다. 몸길이 = 높이 × 0.4 정도라서 200px 이면 약 80px 다.
  - 다만 꼬리·수염까지 폭 안에 들어와야 해서, 폭 220px 에선 높이를 키워도 몸 약 88px 까지만 큰다. 사이드바 폭을 넓히면(320px) 128px 까지 커진다.
  - 폭은 산책 범위와 소품 크기만 줄인다.
    - 폭 < 240px 이면 소품을 0.75배로 줄인다.
    - 소품 자리가 모자라면 엔진의 `room` 으로 돌아앉는다.
- **채팅 바 아래(토글 켬)**
  - 창 맨 아래 한 줄(`.app` 그리드의 셋째 줄)에 사이드바부터 오른쪽 패널 끝까지 전체 폭의 띠를 둔다. 입력창(`.composer`)은 대화 영역에 그대로 있고 띠는 그 아래다. 높이는 같은 손잡이로 120~240px, 기본 170px 이다. 사이드바 자리일 땐 이 줄이 비어 높이 0 이다.
  - 사이드바 패널 자리엔 RPG 게이지·버튼(`CatStatusPanel`)만 남는다.
  - 고양이는 넓게 걷고, 활동 소품도 원래 크기로 쓴다.
- 두 자리 모두 **같은 엔진·감독·캔버스 하나**다. 토글하면 캔버스를 새 자리로 옮기고 `resize` 만 부른다. 고양이 상태(활동·자세·꼬리)는 그대로 이어진다.
- 데스크톱 오버레이(D)는 P4 이후 옵션이다.
