# 네코의 마음 — 설계(초안, 구현 전)

> 사용자: "네코가 단순한 프롬프트로만 작동하기보다 하나의 인격체(묘격체)처럼 동작했으면 좋겠다. 산책만이 아니라 네코가 판단하는 모든 선택에 반영되면 좋겠다. 코드로 굴리지 말고 네코가 스스로 생각해서."

이 문서는 설계만 적는다. 사용자가 OK 하면 1단계부터 만든다.

## 1. 한 줄 요약

네코가 **자기 손으로 쓰는 짧은 노트**(궁금한 것·하고 싶은 것·최근에 고른 것과 이유)를 갖고, 느린 선택(산책 주제, 가져올 선물, 돌아와서 건넬 말, 그릴 것, 요즘 좋아하는 놀이)은 모두 **생각하기 한 단계**를 거친다. 생각하기에는 규칙을 주지 않는다. 대신 날짜와 횟수가 붙은 재료를 주고, 네코가 고르고 이유를 한 줄 남긴다. 실패하거나 시간이 지나면 지금 동작으로 돌아간다.

## 2. 지금은

| 선택 | 지금 누가 고르나 | 근거 |
|---|---|---|
| 산책 주제 | 웹을 도는 하위 에이전트가 그때그때 | 최근 산책 기억 5개만 본다(날짜·횟수 없음) |
| 가져올 선물 종류 | 코드 주사위(`rollGift`, 최근 5번과 겹치지 않게 가중치) | 없음 |
| 선물·보고 글 | 보고 호출(`walk_report`) | 알아본 것·지나온 곳 |
| 혼자 그릴 그림 | `neko-drawing.ts pickTopic` → `think` | 산책 주제와 같은 재료 + 최근에 그린 것 |
| 15초마다 바뀌는 활동 | 감독(`director/needs.ts soloOdds`) | 숨은 게이지(기운·호기심·청결·애정) |
| 돌아와서 건넬 말 | 없음(산책 보고만) | — |

공통점: 네코에게는 "어제의 나"가 없다. 같은 주제를 또 찾아보고, 왜 그걸 골랐는지 남지 않는다.

## 3. 지킬 것

- **시스템 프롬프트를 늘리지 않는다.** 생각하기는 따로 도는 호출이다. 채팅의 시스템 프롬프트와 대화는 그대로다.
- **채팅 대화에 추측 nudge 를 넣지 않는다.** 생각하기의 결과는 대화 기록이나 모델 컨텍스트에 들어가지 않는다(돌아와서 건넬 말은 고양이 말풍선으로만, §6.2).
- **규칙 대신 재료를 준다.** "오래된 건 다시 찾아봐", "자주 본 건 피해" 같은 판단 규칙은 쓰지 않는다. 날짜와 횟수가 보이게 차려 주고 네코가 판단한다.
- **키워드 라우팅을 쓰지 않는다.**
- **격리(78aa8c7)는 그대로다.** 사용자 기억은 생각하기에만 보인다. 웹을 도는 하위 에이전트에는 지금처럼 안 간다. 하위 에이전트에는 고른 주제 한 줄만 넘긴다(§7).
- **실패하면 지금 동작으로 간다.** 시간 초과(20초), 툴을 안 부름, 검사에서 걸림, 예산 초과, 오프라인이면 생각하기 없이 지금처럼 돈다.
- **옛 버전이 깨지지 않는다.** 동기화 기록 형식은 옛 버전이 모르는 칸을 버리는 쪽으로 늘린다(§5.2).

## 4. 속마음 노트

네코가 생각하기를 할 때마다 짧게 남기는 기록이다. 사용자가 보거나 지울 수 있다(설정 › 네코가 기억하는 것 아래에 접힌 칸 "속마음", ~습니다 체 안내).

```jsonc
// settings 키 "neko_mind" (기기 간 동기화, §5.2)
{
  "v": 1,
  // 최근 40개. 오래된 것부터 버린다
  "notes": [
    { "at": "2026-11-19T08:10:00+09:00", "kind": "wonder", "text": "비 오는 날 새들은 어디서 쉴까" },
    { "at": "2026-11-19T08:12:00+09:00", "kind": "chose", "what": "walk_topic", "text": "비 오는 날 새들의 쉼터", "why": "어제 창밖에서 비를 오래 봐서" }
  ],
  // 산책으로 알아본 주제와 날짜. 횟수는 날짜 개수다
  "topics": [
    { "topic": "고양이의 잠", "at": ["2026-11-02", "2026-11-09", "2026-11-15"] }
  ],
  // 요즘 기울기(§6.3). 감독이 가중치로 읽는다
  "lean": { "at": "2026-11-19T13:00:00+09:00", "like": ["yarn", "window"], "tired": ["box"], "why": "털실이 요즘 제일 재밌어" }
}
```

- `kind`: `wonder`(궁금한 것), `want`(하고 싶은 것), `chose`(고른 것과 이유). 글은 한 줄(60자)로 자른다.
- 노트에는 **사용자 기억에서 온 사실(이름·장소·일정)을 적지 않는다.** 노트를 쓰는 생각하기는 사용자 기억을 보지만, 노트는 산책 재료로도 다시 쓰이기 때문이다. 먼저 막는 건 **노트를 쓰는 생각하기(산책 주제·선물 고르기)에 사용자 사실(fact·project·reference)을 아예 보이지 않는 것**이다. 재료엔 취향(preference)만 간다(`mindMaterial` `facts: false`). 사실을 보는 건 이 기기 말풍선으로만 쓰고 노트에 안 남기는 첫마디뿐이다. 그다음 겹으로, 저장 전에 그 줄의 세 글자 조각을 본다(`leaksFact`, 띄어쓰기·문장부호는 빼고). 사실의 조각이 하나라도 있으면 그 줄을 버린다. 취향에도 있는 조각만 넘어간다. 산책 기억·노트는 웹 글이 섞일 수 있어 허용 목록에 넣지 않는다(웹 글이 사실 조각을 허용시키지 못하게, 0.1.20 보안 검토). 관심사를 이어 가는 것이 이 기능의 목적이다. 이름·주소·일정은 사실에만 있어 걸린다. (처음 안은 bigram 겹침 0.5였다. 하지만 "고양이" 같은 흔한 말이 사실에 있으면 고양이 주제가 늘 걸려, 사실에만 있는 조각을 보는 쪽으로 바꿨다.)

## 5. 저장과 동기화

### 5.1 왜 memories 표가 아닌가

매니저 안은 "네코 자신의 기억(kind neko)처럼 저장"이었다. 그런데 memories 표에 두면 문제가 둘 생긴다.

1. **kind `neko` 로 두면** 산책 하위 에이전트가 읽는 "전에 산책하며 알아본 것"(최근 neko 기억 5개)에 노트가 섞인다. 옛 버전도 그렇게 읽는다. 노트는 사용자 기억을 본 단계가 쓴 글이라, 웹을 도는 에이전트에게 가면 격리가 깨진다.
2. **새 kind(`neko_note`)로 두면** 옛 버전(0.1.17 이하)의 기억 검색은 `kind != 'neko'` 만 빼고 찾는다. 그래서 노트가 채팅 회상에 떠오른다.

그래서 **동기화되는 설정 키 하나(`neko_mind`)** 에 둔다(권장). 산책에서 알게 된 사실은 지금처럼 kind `neko` 기억으로 남긴다.

### 5.2 옛 버전

- 새 버전은 `SYNCED_SETTINGS` 와 트리거 SQL 에 `neko_mind` 를 더한다(Rust, 마이그레이션 하나).
- 옛 버전의 `sync::apply` 는 자기 목록에 없는 설정 키를 받으면 건너뛴다(`src-tauri/src/sync/mod.rs` 426줄). 그래서 저장하지도 깨지지도 않는다. 옛 버전은 이 키를 올리지도 않는다.
- 설정 값은 통째로 나중에 쓴 쪽이 이긴다. 두 기기가 같은 분에 노트를 쓰면 한쪽 줄이 빠질 수 있다. 산책은 한 기기만 나가므로(선점, b6ff3c0) 산책 노트는 겹치지 않는다. 졸 때의 기울기 갱신은 겹칠 수 있다. 쓰기 전에 받은 값과 합쳐(at 으로 줄 단위 합집합) 줄인다.

### 5.3 같은 틀: 숨은 게이지(0.1.18, 먼저 들어감)

사용자 결정: 처음엔 "배고픔이랑 심심함만 다르게"였다가(0.1.18), 기기마다 게이지가 따로 움직인다는 걸 알고 "밥·놀이도 같이(한 고양이)"로 바꿨다(0.1.19). 그래서 노트보다 먼저 게이지 전부가 같은 틀(동기화 설정 키)로 옮겨 갔다.

| 키 | 동기화 | 내용 | 쓰는 때 |
|---|---|---|---|
| `neko_needs` | 맥·폰 같이 | 기운·호기심·청결·애정, 잰 때 `at`, 생일 `born` | 어느 게이지든 3 넘게 바뀌었거나 10분이 지났을 때, 산책 귀가 같은 사건 |
| `cat_rpg_state` | 맥·폰 같이(0.1.19, 마이그레이션 9) | 밥·놀이, 오늘 밥 준 횟수, 잰 때 `lastTick`, 생일 | 밥·놀이가 3 넘게 바뀌었거나 10분이 지났을 때, 밥 주기·놀아 주기 |
| `neko_mind`(예정) | 맥·폰 같이 | 노트·주제·기울기(§4) | 생각하기가 끝났을 때 |
| `neko_presence`(0.1.22, 마이그레이션 11) | 맥·폰 같이 | 큰 상태(깨어 있음·자는 중·산책·밥), 적은 때, 그 기기를 마지막으로 쓴 때, 기기 | 가장 최근에 쓴 기기의 큰 상태가 바뀔 때, 다른 기기를 따르던 기기를 쓰기 시작할 때. 다른 기기는 감독 입력으로 따른다(`src/neko/presence.ts`) |

- 값과 잰 때(`at`, `lastTick`)를 같이 둔다. 받는 쪽은 그때부터 지난 시간만큼 줄여 읽는다(`needsStore.pull`, `useCatRpg newerRemote`). 내가 쓴 것보다 이전에 잰 값은 무시한다. 충돌은 동기화의 (ts, 기기) 승자 규칙 그대로다.
- 생일은 가장 이른 날로 맞춘다. 기기마다 처음 켠 날이 달라 DAY 수가 달랐다. `cat_rpg_state` 도 생일을 갖지만 나중에 쓴 기기가 이기는 키라 늦은 날이 이길 수 있어, 가장 이른 날은 `neko_needs` 의 `born` 이 맡는다.
- 키를 나눈 까닭: 설정 값은 통째로 나중에 쓴 쪽이 이긴다. 게이지(10분에 한 번)와 노트(드물게)를 한 값에 두면, 게이지를 쓰는 기기가 다른 기기의 새 노트를 덮는다. 그래서 쓰는 박자가 다른 것은 키를 나눈다.
- 옛 버전(0.1.17)은 `neko_needs` 를 받으면 버린다(목록에 없는 키, 경고 로그 한 줄). 새 버전은 마이그레이션 6에서 설정 트리거를 지금 목록으로 다시 만들고, 있던 값을 올릴 거리로 찍는다.

## 6. 생각하기 한 단계

`src/agent/neko-mind.ts` 의 `think(choice, material)` 하나를 느린 선택이 모두 같이 쓴다.

- **호출**: `fetchCompletionMessage` 한 번. 툴 하나(`neko_think`)로 답하게 한다. 웹 도구는 없다. 생각(thinking)은 모델 설정대로 둔다.
- **시스템 글**: "너는 고양이 {이름}. neko_think 툴로 답해." + 사용자가 정한 성격(지금 산책 보고와 같은 `persona()`). 판단 규칙은 없다.
- **사용자 글(재료)**: 선택마다 아래 덩이 중 필요한 것만 싣는다.
  - `지금`: 날짜·요일·시각대, 날씨(있으면), 숨은 게이지(기운·호기심·청결·애정, 0–100), 밥·놀이 게이지.
  - `내 노트`: 최근 노트 20줄, 날짜가 붙은 채로.
  - `내가 알아본 주제`: 주제마다 횟수와 날짜("고양이의 잠 — 3번: 11/2, 11/9, 11/15").
  - `산책에서 알게 된 것`: neko 기억(지금처럼 120자 이하), 날짜와 떠올린 횟수(`created_at`, `use_count`).
  - `사용자에 대해 아는 것`: 사용자 기억(취향·관심 위주로 12개), 날짜가 붙은 채로.
  - `고를 것`: 이번 선택의 보기(예: 선물 종류 중 지금 가능한 것).
- **출력(툴 인자)**: `{ pick: string, why: string, note?: { kind: "wonder"|"want", text: string } }`. `pick` 은 선택마다 검사한다(보기에 있는가, 길이, §7의 겹침). 통과하면 `chose` 노트와 함께 저장하고, 아니면 버리고 지금 동작으로 간다.
- **시간 제한**: 20초(`AbortSignal.timeout`). 산책 출발을 붙잡지 않게 출발 전에 미리 돌리지 않고, 산책을 나간 뒤 하위 에이전트 앞에서 돈다.
- **어느 모델**: 지금 쓰는 프로필 그대로다. 산책(1·2단계 일부)은 지금처럼 Claude 프로필에서만 돈다. 기울기와 그림 고르기는 작은 로컬 모델에서도 돌고, 실패하면 지금 동작으로 간다.

### 6.1 1단계 — 산책 주제

1. 산책을 나가면 `think("walk_topic")`. 재료는 `지금`, `내 노트`, `내가 알아본 주제`, `산책에서 알게 된 것`, `사용자에 대해 아는 것`.
2. 고른 주제 한 줄(40자 이하)만 하위 에이전트의 과제에 넣는다: "이번엔 '{주제}'가 궁금해서 나왔어." 하위 에이전트가 받는 다른 것은 지금과 같다.
3. 보고 호출(`walk_report`)에 `next_wonder`(다음에 궁금한 것 한 줄)를 더한다. 그 줄은 `wonder` 노트가 되어 다음 산책의 재료로 이어진다.
4. `topics` 에 오늘 날짜를 더한다(주제 글이 같으면 같은 주제로 센다. 재료에 기존 주제 이름을 보여 주니 다시 갈 땐 같은 이름을 쓰게 된다).
5. 실패하면 지금처럼 하위 에이전트가 스스로 고른다.

0.1.22(사용자: "산책을 고양이 연구로만 찾는다"): 재료가 거의 다 고양이 얘기라 고를수록 고양이로 쏠렸다. 규칙을 더하지 않고 재료를 넓혔다.
- 주제를 고를 때 네코가 그 주제의 갈래(한두 낱말)를 스스로 붙인다(`field`). 재료엔 "최근 10번의 갈래: 동물 8번, 날씨 1번…" 묶음이 붙는다. 낱말로 가르는 코드 분류는 없다.
- 고양이가 아닌 재료: 계절·날씨(창문이 받은 지금 날씨), 이번 산책에 지나는 곳 이름, 사용자가 요즘 이야기한 관심 낱말이다. 관심 낱말은 최근 대화 제목 10개를 생각 끈 작은 판정이 하루 한 번 일반어 3~5개로 바꾼 것이고, 사용자 사실 조각이 든 낱말은 버린다(`recentInterests`, 이 기기에만 `neko_interests`).
- 성격 글·시스템 프롬프트는 그대로다. 실서버 분포 확인은 `neko-mind.real.test.ts`(로컬 모델이 떠 있을 때만).

"오래된 기억은 오랜만에 다시, 자주 본 건 피하기"는 규칙으로 쓰지 않는다. 날짜와 횟수가 보이게 줄 뿐이고, 판단은 네코가 한다.

### 6.2 2단계 — 선물·첫마디·그림

- **가져올 선물**: 알아본 뒤 `think("walk_gift")`. 보기는 지금 가능한 종류(`giftWeights` 의 available)다. 재료에는 최근 선물 기록(날짜·종류)과 알아본 것 요약을 넣는다. 실패하면 `rollGift` 주사위로 간다. 재료 준비(장소·날씨·기억 고르기)는 지금 코드 그대로다.
- **돌아와서 먼저 건넬 말**: 졸기 시작할 때 도는 생각하기(§6.3)가 한 줄을 같이 남긴다. 사용자가 돌아오면(졸음이 깸) 고양이 말풍선으로 한 번 보이고 버린다. 채팅 기록·모델 컨텍스트에는 넣지 않는다. 6시간이 지나면 버린다.
- **무엇을 그릴지**(2026-11-23, 사용자: 그릴 거리를 좁히지 말고 산책 주제와 같게): `neko-drawing.ts pickTopic` 이 산책 주제와 같은 `think` 를 부른다. 재료는 `mindMaterial`(노트·알아본 주제·산책 기억·사용자 취향·요즘 관심)에 날짜 붙은 "최근에 그린 것"을 더한 것이다. 고를 것에는 그리는 방식(도형 몇 개, 액자)만 적고, 갈래나 예시 이름은 주지 않는다. 그림을 건넬 말은 `say` 칸으로 받는다. 고른 이유는 `chose` 노트로 남긴다. 호출 수는 늘지 않는다.

### 6.3 3단계 — 요즘 기울기

- 15초마다 바뀌는 활동은 지금처럼 코드(감독·스케줄러)가 고른다.
- 졸기 시작할 때와 산책에서 돌아올 때 `think("lean")` 이 돈다(두 번 사이 2시간 이상). 보기는 혼자 놀기 후보(`SOLO_KEYS`)다. 재료는 최근 이틀 동안 한 활동과 횟수(감독이 세어 둔 것), 숨은 게이지, 노트다. 결과는 `like`(1–3개), `tired`(0–2개), 이유 한 줄이다.
- 지금(0.1.19) 감독이 혼자 놀기를 고르는 틀: 모자란 숨은 게이지를 채우는 활동일수록 점수가 높다(호기심이 모자라면 창밖·선물·책, 청결이 모자라면 그루밍). 기운은 넘치면 뛰는 놀이, 바닥이면 쉬는 놀이 쪽이다. 보이는 놀이 게이지도 같은 틀에 들어간다. 심심하면(낮으면) 기운을 쓰는 놀이(털실·나비·선물)가 오르고, 차 있으면 다른 걸 한다. 직전과 그 앞에 한 것은 고르지 않는다. 선물 놀이는 한 판에 물건 둘과 놀고 끝나는 한 번짜리라, 다른 놀이와 번갈아 나온다. 기운이 30 아래면 선물과도 움직이는 놀이 대신 곁에서 냄새를 맡거나 기댄다(엔진 `playFor`).
- 감독은 `soloOdds` 에서 `like` 는 ×1.6, `tired` 는 ×0.5 로 곱한다. 이 숫자는 코드의 손잡이다. 기울기가 하루 넘게 갱신되지 않으면 1로 돌아간다.
- 졸 때 도는 같은 호출이 §6.2 의 "돌아와서 건넬 말"도 남긴다(호출 하나).

## 8. 호출 수와 비용

지금 하루 산책은 정기 3번(아침·점심·저녁, 지난 산책 1시간 뒤)에 3시간 간격 산책이 더해져 보통 2–4번, 하루 내내 비워도 7번 정도다(0.1.25).

| 생각하기 | 언제 | 하루 |
|---|---|---|
| 산책 주제 | 산책마다 1 | 2–6 |
| 가져올 선물 | 산책마다 1 | 2–6 |
| 기울기 + 첫마디 | 졸기 시작·산책 귀가, 2시간 간격 | 최대 6 |
| 그림 고르기 | 지금 있는 호출에 재료만 더함 | +0 |
| 꿈(0.1.25) | 길게 깊이 잘 때, 하루 2번·3시간 간격. 생각하기 1 + 그림에 없으면 선물 그리기 2(그리기·고치기) | 0–6 |
| **합계** | | **보통 7–12, 많아야 24** |

호출마다 입력은 약 2–4천 토큰(재료), 출력은 약 200 토큰이다. 꿈의 선물 그리기는 한 번에 입력 약 1–2천(그리는 법·고칠 그림 256px), 출력 약 1천 토큰(도형 목록) 두 번이다. 하루 많아야 입력 8만, 출력 1만 토큰쯤이다. 지금 산책 하나(하위 에이전트의 검색 여러 번 + 보고 + 선물 그리기 둘 + 기억 겹침 판정)보다 작다. 기존 예산 막기(`budgetBlockReason`)를 그대로 거친다. 예산이 막히면 생각하기 없이 지금 동작으로 간다.

### 8.1 꿈(0.1.25, 사용자: 중간중간 잘 때 꿈을 꾸게)

- **언제**: 누워 깊이 잔 지 20분(졸기 5분 → 깊은 잠 6분 → +20분, `src/neko/dream.ts` `DREAM_AFTER_MS`)이 지나면. 하루 두 번(`DREAMS_PER_DAY`)·3시간 간격(`DREAM_GAP_MS`)까지 — 노트의 '꿈'으로 세니 맥·폰이 같이 센다. 다른 기기가 앞이면(presence) 그쪽이 꾼다. 산책·밥 먹는 중엔 안 꾼다. 한 번 해 보면(실패해도) 3시간 동안 다시 안 해 본다.
- **무엇을**: `dreamThink` 한 번. 재료는 노트·알아본 주제·산책 기억·사용자 취향(사실은 안 보인다 — 꿈이 노트가 된다)과 '그림으로 있는 것'(최근 선물·가진 가구, 12개까지, 번호). 예시 글귀·예시 물건은 주지 않는다(사용자: 편향되는 예시는 싫다). 답: `pick` 꿈 한 줄, `see` 그림 번호, 없으면 `draw` 꿈에 나온 것, `greet` 깨서 꿈 얘기를 하고 싶을 때만 첫마디.
- **그림**: 고른 번호의 모양(선물 모양 또는 가구) — 없으면 `draw` 를 선물 그리기(`drawGift`)로 새로 그린다. 그림이 없으면 꿈 없이 잔다.
- **보이기**: 엔진 `dream(content)` — 누워 자는 중이면 머리 위 꿈 말풍선(디자이너 `dream-art.js`)을 0.6초 피워 7초 머물고 접는다. 깨거나 잡히면 바로 접는다. 화면 자리(마당)는 대리 컨트롤러가 화면 창 엔진으로 넘긴다.
- **남기기**: 노트에 '꿈' 한 줄(속마음 칸에 보인다), `greet` 가 있으면 첫마디(이 기기 말풍선, 깰 때 한 번)로.
- **실패**: 생각하기 실패·시간 초과(20초)·예산 막힘·사용자 사실 조각·그사이 깸·그림 없음이면 꿈 없이 그냥 잔다.
- 옛 버전은 노트의 '꿈' 줄을 모르는 종류로 버린다(그 기기가 노트를 다시 쓰면 꿈 줄이 사라진다).

### 8.2 제 상태 알기(0.1.28, 사용자: 지금 제 모습·색을 확인하고, 하는 일을 스스로 알게)

- **최근 행동 기록**(`src/neko/selfState.ts`): 엔진 상태 글자(`label` 이벤트 — 화면 자리면 화면 창이 `neko-evt` 로 넘긴다)가 바뀔 때 이 기기 localStorage(`neko_self_log`)에 6시간치. 20초 넘게 이어진 것만 시작·끝과 함께 남고(돌아다니며 몇 초씩 바뀌는 쉬기·걷기는 안 남는다), 같은 것이 1분 안에 다시 오면 한 줄로 잇는다. 읽을 때 산책 기록(`neko_walk`)과 노트의 '꿈'을 시각 순으로 이어 붙인다. 동기화하지 않는다.
- **첫마디 재료**: 쉴 때 생각하기(§6.2 `restThink`)에 "최근 몇 시간 내가 한 일"로 넣는다. 꺼낼지 말지는 네코가 정한다. 첫마디는 지금처럼 졸기 시작할 때 생각해 두니 그때까지의 기록이다(자리 비운 동안의 꿈은 꿈의 `greet` 가 첫마디를 바꾼다).
- **내부 도구 `neko.self`**: 지금 모습(꾸미기 값을 사람이 읽는 말로)·털 색·있는 곳(방·거실·마당)·지금 하는 일·게이지(배고픔·놀이·기운·호기심·청결·애정)·큰 상태(깨어 있음·졸거나 자는 중·산책·밥)·최근 기록을 돌려준다. 네코가 필요하다고 볼 때 스스로 부른다 — 매 질문에 붙이지 않는다. 시스템 프롬프트엔 도구 목록 한 줄만(native 는 도구 스키마 하나).
- **안 보이게**: 루프가 이벤트 없이 실행한다(`agent-context` `INTERNAL_TOOLS`) — 채팅 도구 표시·네코 도구 동작이 없고, 끝 스텝(저장·대화 기록의 지난 도구 호출)에서 빠진다. 결과는 그 요청 안에서만 모델이 본다. 맥·폰 둘 다.
- **비용**: 부를 때만 결과 약 300–600 토큰. 첫마디 재료는 기존 호출에 몇 줄 더할 뿐이다.

## 9. 만드는 순서와 확인

1. **1단계**(만듦, 0.1.20): `src/agent/neko-mind.ts`(think·노트 저장·`leaksFact`), `neko_mind` 동기화(마이그레이션 10), 산책 주제(`walk.ts` 0번), `next_wonder`, 설정의 "{이름}의 속마음" 칸(기억 칸 아래, 맥·폰 같은 자리, 5개씩·하나씩 지우기).
   - 테스트: 툴을 안 부름·시간 초과·보기 밖 값·사용자 사실과 겹치는 주제이면 지금 동작으로 간다. 하위 에이전트 과제에 사용자 기억 글이 없다(지금 walk.test 의 격리 검사를 넓힌다). 옛 형식 설정·모르는 키를 받아도 깨지지 않는다.
2. **2단계**(만듦, 0.1.20): 선물 고르기(`chooseAmong`, 안 되면 `rollGift`, 선물 기록에 날짜), 첫마디(졸기 시작할 때 `prepareGreeting` 2시간에 한 번 → 깰 때 `takeGreeting` 6시간 안 것만 한 번, 네코 자리 말풍선 7초 — 이 기기에만 `neko_greeting`), 그림 고르기 재료(노트·날짜 붙은 전에 그린 것, 고른 까닭을 노트에). 3단계에서 첫마디 호출이 기울기도 같이 낸다.
3. **3단계**(만듦, 0.1.20): 기울기와 감독 가중치. 졸기 시작할 때(첫마디와 같은 호출)와 산책에서 돌아왔을 때 `restThink` 가 돈다(2시간에 한 번). 재료엔 최근 이틀 한 혼자 놀기와 횟수(이 기기의 `neko_activity_days`, 감독이 활동이 바뀔 때 센다)가 붙는다. 결과는 `neko_mind.lean`(좋아하는 것 1–3, 질린 것 0–2, 맥·폰 같이)이다. 감독은 `soloOdds` 에서 좋아하는 것 ×1.6(`LIKE_K`), 질린 것 ×0.5(`TIRED_K`)를 곱하고, 하루 넘은 기울기는 무시한다(`currentLean`).
   - 테스트: 기울기가 있으면 like 가 더 자주, tired 는 덜 고른다. 하루 넘은 기울기는 무시한다.
