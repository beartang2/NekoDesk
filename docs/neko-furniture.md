# 네코의 가구 — 설계(초안, 구현 전)

> 사용자가 정한 것(0.1.24): 기본 가구 다섯 개(조명·2층 캣타워·캣휠·소파·상자)와 네코 활동, 방 2개·거실 4개·마당 없음, 한 번 놓으면 못 옮기고 꾹 누르기(맥은 우클릭도)로 "치우기"만, 선물함의 "기본 가구" 탭, 산책에서 가끔 가구를 물어온다, 폰은 거실이 넓어 보이게 전체를 줄인다(맥은 그대로).
> 마당은 가구가 없다 — "마당은 열려 있는 창이나 내 마우스 커서에 대해서만 상호작용하게."

이 문서는 설계만 적는다. 사용자가 OK 하면 활동부터 만든다. 그림·UI·폰 크기 칸(§9–§11)은 디자이너가 채운다.

## 1. 한 줄 요약

가구는 선물과 다른 종류의 물건이다. 정해진 자리(칸)에 고정되고, 네코가 그 위·안에서 논다. 감독은 "그 자리에 놓인 가구"가 있을 때만 그 활동을 혼자 놀기 후보에 넣는다(지금 선물 놀이·창 탐험과 같은 방식). 고르는 무게는 지금 needs 점수와 네코의 마음 기울기를 그대로 쓴다.

## 2. 가구 다섯 개와 활동

| 가구 | 활동 키 | 네코가 하는 것 | 채움(needs, 활동 섞기 fills) | 한 번짜리? |
|---|---|---|---|---|
| 조명 | `lamp` | 다가가 앞발로 톡 쳐서 켜거나 끈다 | 호기심 +5 | 예(약 3초) |
| 2층 캣타워 | `cattower` | 1층·2층으로 뛰어오르고 내려온다. 2층에서 잠깐 두리번 | 기운 −15, 호기심 +15 | 아니오(감독이 그만하게) |
| 캣휠 | `wheel` | 올라타 달린다(바퀴가 돈다). 가끔 멈춰 숨 고르기 | 기운 −25, 호기심 +5 | 아니오 |
| 소파 | `sofa` | 올라가 앉거나 식빵, 졸리면 누워 잔다 | 기운 +10, 애정 +5 | 아니오 |
| 상자 | `box` | 들어가 쉰다(지금 상자 놀이를 이 가구로 옮긴다) | 지금 `box` 그대로(기운 +5, 호기심 +10) | 아니오 |

- **지금 상자 놀이를 옮긴다(권장).** 지금은 상자가 어디선가 '뿅' 나왔다 사라진다. 옮긴 뒤엔 상자 가구가 놓인 자리에서만 들어간다. 상자 가구가 없으면 `box` 는 후보에서 빠진다. 감독이 쓰던 '상자 층(혼자 놀기)'의 이름은 그대로 둔다(활동 이름과 다르다).
- **소파와 잠**: 소파가 놓여 있으면 졸릴 때 소파로 가서 눕는다(감독의 잠 층이 "잘 자리"로 소파를 고른다). 없으면 지금처럼 그 자리에서 잔다.
- **조명은 '원할 때'**: 조명 활동은 바뀔 까닭이 있을 때만 후보가 된다. 밖이 어두운데 꺼져 있거나(창밖 빛 `skyAt` 가 노을·밤), 밝은데 켜져 있거나, 잠들려는데 켜져 있을 때다. 규칙은 이 조건 하나뿐이고, 언제 켤지는 다른 놀이와 같은 무게로 섞여 정해진다.
- 새 활동은 `activity-mix.js` 의 MIX 에 선언만 더한다(`solo`·`fills`·`maxMs`). 감독 코드는 "놓인 가구가 있나"만 본다.

## 3. 감독·네코의 마음과 잇기

- **후보 조건**: `soloOdds` 에 `furniture: Set<활동 키>` 를 더해, 지금 장소에 그 가구가 놓였을 때만 후보에 넣는다. 선물 놀이(`hasGifts`)·창 탐험(`towerOk`)과 같은 방식이다.
- **무게**: 지금 needs 점수 그대로다. 모자란 게이지를 채우는 활동일수록 오르고, 기운이 넘치면 뛰는 놀이(캣타워·캣휠), 바닥이면 쉬는 놀이(소파·상자)가 오른다. 보이는 놀이 게이지도 지금처럼 들어간다(심심하면 뛰는 놀이).
- **네코의 마음**: 기울기(`restThink`)의 보기는 `SOLO_KEYS` 라, 가구 활동도 저절로 "요즘 좋아하는 것·질린 것"이 될 수 있다(×1.6·×0.5). 놓이지 않은 가구는 고를 수 있어도 후보 조건에서 빠진다.
- **연달아 막기**: 지금처럼 직전과 그 앞에 한 혼자 놀기는 안 고른다.

## 4. 데이터 모양·저장·동기화

```jsonc
// 동기화 설정 키 "neko_furniture"(마이그레이션 12) — 놓인 기본 가구와 산책에서 물어온 가구
{
  "v": 1,
  "items": [
    // 기본 가구는 코드 상수라 놓였을 때만 적힌다(place)
    { "id": "base:sofa", "kind": "sofa", "place": { "at": "dock", "slot": 2 } },
    // 산책에서 물어온 가구: 이름·설명·모양, 그리고 다섯 활동 중 무엇처럼 쓰는지(kind)
    { "id": "walk:3f2a", "kind": "sofa", "title": "낡은 등나무 의자", "body": "공원 벤치 옆에서 봤어", "shape": { "v": 1, "parts": [] }, "found": "2026-11-20", "place": null }
  ]
}
```

- **칸(slot)**: 가구는 자유 자리가 아니라 정해진 칸에 놓인다. 방은 칸 2개(왼쪽·오른쪽), 거실은 칸 4개(띠를 넷으로 나눈 가운데)다. 비율 자리라 무대 크기가 바뀌어도 같은 칸이다. 칸이 있어서 겹침 판정도, "꽉 참" 판정도 간단하다(§6).
- **고정**: 가구는 끌어서 옮길 수 없다. 꾹 누르기(맥은 우클릭도)는 선물의 "정리"와 같은 자리에 "치우기" 버튼 하나만 띄운다. 치우면 `place: null` 이 되어 가구 탭에 남고, 다시 놓을 수 있다.
- **조명 켜짐**: 기기마다 둔다(동기화 안 함). 켜고 끄는 건 그 순간의 활동이고, 큰 상태(잠·깸)는 이미 `neko_presence` 로 맞춘다.
- **동기화**: 값 하나를 통째로 덮어쓴다(나중에 쓴 기기가 이긴다). 놓기·치우기·물어오기는 드물어 충돌이 거의 없다. 선물처럼 하나씩 합치는 동기화(`gift_add`)는 이번엔 하지 않는다. 한 기기에서 놓는 사이 다른 기기에서 물어온 가구가 덮이면, 물어온 기기가 다음에 쓸 때 합친다(`id` 로 합집합).
- **옛 버전**: 모르는 키라 버린다. 가구 활동 키가 감독에 오더라도 옛 엔진엔 없는 활동이라 `act()` 가 무시한다.
- **선물과의 관계**: 가구는 선물함 배열(`neko_gifts`)에 넣지 않는다. 넣으면 옛 버전이 선물로 그려 끌고 다닌다.

## 5. 산책에서 가구 물어오기

- 선물 종류에 `furniture` 를 더한다(`walk.ts` GIFTS). 드물게만 나온다. 기본 무게는 낮게 두고, 최근 7일 안에 물어왔으면 보기에서 뺀다.
- 무엇을 가져올지는 지금처럼 네코가 고른다(`chooseAmong`, 날짜 붙은 최근 선물 기록이 재료다). 고르면 보고 호출(`walk_report`)이 이름·설명과 함께 `furniture_kind`(다섯 활동 중 하나)를 낸다. 모양은 지금 선물처럼 `drawGift` 로 그린다(크게, §9 참고).
- 들어가는 곳은 가구 탭이다. 설명과 함께 보이고, 놓으면 그 `kind` 의 활동을 한다. 예: "등나무 의자"는 소파처럼 쓴다.
- 산책 하위 에이전트·격리 규칙은 그대로다(가구 고르기는 선물 고르기와 같은 길이다).

## 6. 방 2개·거실 4개 판정

- 칸 수가 곧 상한이다. `place(id, at)` 은 그 장소에 빈 칸이 있을 때만 놓고, 없으면 거절한다. 그러면 UI 가 "자리가 꽉 찼습니다"를 보이고, 치우기를 먼저 하라고 안내한다(문구는 디자이너).
- 맥·폰이 같다. 가로 화면(네코만 보기)은 거실 그대로다.
- 마당엔 놓는 버튼이 없다(장소 목록에서 뺀다).
- 선물과 가구는 겹쳐도 된다. 가구가 뒤, 선물·고양이가 앞에 그려진다. 고양이가 가구 칸 앞을 지나가는 건 지금 선물과 같다.

## 7. 크기와 폰

- 가구 크기는 고양이 키 단위(S 배율)로 정한다. 그래서 무대 배율이 바뀌면 같이 커지고 줄어든다. 디자이너의 폰 70%(stage-scale `K`)도 따로 손댈 것 없이 따라간다.
- 기준 키(고양이 키 100 = 1): 조명 1.5, 2층 캣타워 1.8(1층 발판 0.8·2층 1.5), 캣휠 지름 1.3, 소파 높이 0.9·폭 2.2, 상자 0.8.
- 들어가는지(거실이 가장 낮다): 폰 세로 거실(띠 120, K 0.7 → S 약 0.33)은 캣타워가 약 60px 로 띠(바닥 114) 안에 든다. 맥 거실(170)도 키의 2.4배 상한 안이다. 방은 넉넉하다.
- 캣타워 2층·소파 위는 엔진의 '올라앉는 면'(지금 마당 창 위에 쓰는 perch: `surfaceAt`·`settleSurface`)을 무대 모드에도 켜서 쓴다. 가구가 면을 내놓는다(발판 윗변 y·x 범위).

## 8. 조명과 방 빛

- 지금 방 빛은 창밖 하늘과 같은 계산(`skyAt`)으로 벽·바닥을 노을엔 따뜻하게, 밤엔 어둡고 푸르게 덮는다(Wallpaper `SkyTint`, 1분에 한 번).
- 조명이 켜지면 그 둘레에 따뜻한 빛 웅덩이(radial gradient)를 `SkyTint` 위에 그린다. 밤 덮개를 조명 둘레만 걷어 내는 셈이다. 낮엔 거의 안 보이게 약하게 둔다.
- 엔진은 켜짐이 바뀔 때 `lamp` 사건(`{ on }`)을 내고, 호스트(NekoSlot·RoomBackdrop)가 빛 웅덩이를 다시 그린다. 빛은 멈춘 그림이라 프레임마다 다시 그리지 않는다.
- 조명은 네코가 켜고 끈다. 사용자 버튼은 없다(사용자 결정: "네코가 원할 때").

## 9. 그림(디자이너)

_디자이너가 채운다: 다섯 가구의 그림체(선물 팔레트·면 입체·INK 그늘), 캣휠 회전, 조명 빛, 산책 가구를 크게 그릴 때의 규칙._

## 10. UI(디자이너)

_디자이너가 채운다: 선물함 "기본 가구" 탭(다섯 개 + 물어온 가구, 설명), 놓기·치우기, 꽉 참 안내, 꾹 누르기·우클릭 "치우기" 버튼._

## 11. 폰 크기(디자이너)

_디자이너가 채운다: 폰 거실·방 70% 배율(stage-scale `K`), 창문·선물·가구가 같이 줄어드는 기준, 가로 화면._

## 12. CPU

- 가구는 대부분 멈춘 그림이다. 엔진 캔버스에 매 프레임 그리지 않고, 무대 아래 정지 그림 층(지금 빈 방의 `RoomGifts` 와 같은 길)에 놓이거나 치울 때만 그린다. 그래서 가만히 있을 땐 프레임 비용이 늘지 않는다.
- 움직이는 건 활동 중일 때만 엔진이 그린다: 돌아가는 캣휠, 톡 쳐서 흔들리는 조명. 활동이 끝나면 정지 그림으로 돌아간다.
- 프레임 정책(30fps, 졸 때 15, 멈춤 0)은 그대로다. 캣휠을 달리는 동안은 '깨어 있음'(30)이다.
- 조명 빛은 SVG 덮개라 켜고 끌 때만 다시 그린다.

## 13. 만드는 순서

1. 엔진 활동 다섯(하네스 QA): 가구 칸·모양 상수, 무대 모드 perch(캣타워 2층·소파 위), `cattower`·`wheel`·`sofa`·`lamp`, 상자 놀이를 가구 상자로 옮기기.
2. 감독: 후보 조건(`furniture`), MIX 선언, 소파에서 자기.
3. 저장·동기화: `neko_furniture`(마이그레이션 12), 놓기·치우기·꽉 참, 옛 버전 무시 확인.
4. 조명 빛(호스트), 가구 탭·치우기 UI(디자이너).
5. 산책 가구 물어오기.

시험: 가구가 놓였을 때만 그 활동이 후보에 든다. 칸이 차면 놓기를 거절한다. 치운 가구를 다시 놓을 수 있다. 옛 형식·모르는 키를 받아도 깨지지 않는다. 하루치 시뮬레이션에서 한 활동이 30%를 넘지 않는다(지금 needs 시험과 같다). 캣타워·소파 위에서 떨어지거나 무대 밖으로 나가지 않는다.

## 14. 정할 것(사용자)

1. 지금의 상자 놀이를 상자 가구로 옮길까요? 옮기면 상자 가구를 놓지 않은 자리에선 상자 놀이가 없어집니다(권장).
2. 소파가 놓여 있으면 졸릴 때 소파로 가서 잘까요(권장)? 아니면 지금처럼 그 자리에서 잘까요?
3. 산책에서 가구를 물어오는 빈도: 일주일에 한 번쯤(권장)이 적당할까요?
